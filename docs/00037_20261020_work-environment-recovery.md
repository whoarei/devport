# 工作环境恢复

日期：2026-10-20。首版实现工作区、文件标签、编辑位置、未保存草稿、目录树、终端标签、窗口状态和文件传输面板恢复。运行控制台的选中任务、输出及进程不加入恢复记录。

## 保存位置与范围

本机应用配置目录的 `work-environment.json` 保存版本 1 的快照，Windows 通常为 `%APPDATA%/com.devrunner.remote-runner/work-environment.json`。无需在源工作区、`.runner` 或目标设备写入此类客户端状态。原有布局、最近工作区、运行设置和文件传输目录仍使用已有存储。

快照记录：

- 当前工作区 `WorkspaceRef`；主动关闭工作区后记录 `null`，不根据最近列表擅自重新打开。
- 最近 10 个工作区的文件标签顺序、活动文件、编辑器语言、光标/选区、横纵滚动位置、展开目录和目录树滚动位置。切换回已访问工作区时同样恢复其视图。
- 脏标签的完整编辑内容、保存前内容、文件 revision、换行类型和 BOM。干净文件只保存描述，不缓存正文。
- 最多 8 个终端的标签 ID、设备 ID、原工作区与起始子目录、活动终端。运行控制台用活动终端 `null` 表示，但不记录其任务或输出。
- 窗口的普通状态大小（逻辑像素）、位置（物理像素）及最大化状态。
- 文件传输面板最后选择的设备、显示隐藏文件和排除仓库/依赖选项。各端浏览目录继续由已有目录偏好恢复；不恢复文件勾选或自动开始传输。

文件标签和展开目录各限每工作区 256 项；草稿正文、保存前正文分别限 1 MiB；整个快照限 32 MiB。超过限额会明确显示保存失败并保留旧快照，不静默截断草稿或覆盖原文件。

## 保存与退出

前端监听上述状态变化，500 ms 防抖后提交；不因运行输出或终端轮询状态变化反复保存。写入串行化，已有写入期间的新修改会接着写入，旧响应不能覆盖较新快照。页面失焦/隐藏时尽力刷新，正常退出及安装更新前等待刷新完成。

Rust 边界验证版本、工作区路径、相对路径、条目数、重复项、草稿大小和窗口数值。读文件最多读取上限加一字节；损坏、不兼容或超限记录保留原样，显示恢复失败，此次启动不覆盖原记录。写入采用同目录 UUID 临时文件、完整写入并 `sync_all`，随后原子替换；写失败保留上次成功快照。Unix 文件权限为 0600。

正常退出仍走既有保存/丢弃/取消确认。选择丢弃后，该草稿从恢复记录中移除；若随后取消退出或重新加载失败，则恢复草稿备份资格。退出清理终端前刷新快照，清理造成的标签清空不作为用户主动关闭标签保存。用户在正常操作中关闭终端/文件标签，则从下次恢复记录中移除。

防抖尚未提交的最后 500 ms 左右改动可能在进程被强制终止时丢失；该机制不等同于每次输入都同步落盘。

## 启动与按需读取

先读取本机快照并加载设备配置，再还原工作区、文件/终端标签和文件传输选项。启动期间用户主动打开的工作区、终端或修改的选项优先，较晚到达的恢复响应不能覆盖这些操作。

优先读取活动文件，其他文件只在激活或保存时读取。还原展开的目录按父级到子级读取，只访问可见且确实存在的目录，不扫描整棵工作区。窗口及文件传输面板在已有启动流程中恢复，文件传输不会在恢复选项就绪之前误选默认设备。

离线、文件丢失或读取失败时保留标签和草稿，允许重试。干净但尚未读回的文件保持只读，不能将空占位正文写回来源。草稿恢复后不自动写入源文件；若源文件 revision 已变化，保留旧 revision 并标记冲突，已有保存 CAS 校验继续阻止覆盖外部修改。用户重新加载时仍询问如何处理草稿。

编辑器仍使用 CodeMirror 实例内的撤销历史；跨启动不恢复撤销栈。恢复选区在当前正文长度内截断，滚动位置由实际布局约束。

## 终端与窗口

终端仅还原标签及起始参数，显示“连接”入口。连接时使用当前设备配置建立新会话，不复用旧 `session_id`，不重放命令、恢复进程或恢复临时环境变量。应用尚未跟踪 shell 中后续 `cd` 后的目录，只恢复打开终端时的目录；串口依旧不支持独立终端。

窗口恢复依据当前显示器工作区与 DPI 约束普通大小，失联显示器的位置移回可用屏幕，保留最大化及所在显示器意图。最小化状态不作为下次启动状态；`--minimized` 自动启动仍遵循托盘静默启动，隐藏窗口不会因恢复最大化而弹出。

## 验证

前端回归覆盖按需读取、草稿及外部冲突、离线/缺失文件、未读取草稿的保存、丢弃与取消、用户操作优先、终端重新连接与退出清理、跨工作区视图、串行写入、保存失败重试和坏记录保护、显示器/DPI 计算。Rust 回归覆盖原子替换、完整草稿读回、路径与数量/大小校验，以及坏记录、超限记录的保留。

浏览器预览通过模拟存储和文件服务，验证活动文件、编辑后草稿、展开目录、终端标签及文件传输选项跨刷新恢复。真实 SSH/物理串口不作为测试依赖；原生窗口跨显示器拖动及桌面自动启动行为需要实际桌面环境进一步验证。

`npm test`（188 项）、`npm run build`、`cargo fmt --all -- --check`、`cargo test --offline --all-targets --target-dir target/transfer-verification`（280 项通过、20 项可选测试默认跳过）及 `git diff --check` 通过。Rust 全套使用独立输出目录，未停止用户正在运行的应用。
