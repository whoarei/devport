# DevPort v1.0.1

## 修复

- 修复旧版受管 Python 缓存含 uv 版本别名目录联接（junction）时，迁移失败并阻止应用启动的问题。
- 迁移时保留旧 `runtime-v1` 缓存，不将含绝对路径的 Python 环境搬到新目录；设备、历史、日志、工作环境和草稿照常导入，可搬移的 `uv-assets` 下载缓存继续复用。
- 迁移错误区分数据占用与其他原因；用户数据中的链接仍拒绝跟随，并报告具体路径，不再将所有失败统一提示为“关闭旧版后重试”。
- 同步迁移与 Python 环境文档，明确运行时缓存需要在 DevPort 新目录重新准备。

## 验证范围

- 前端 467 项测试、TypeScript 与 Vite 构建通过。
- Rust 全目标 324 项测试通过，20 项环境相关测试按默认设置跳过；格式与差异检查通过。
- 新增真实 Windows junction 回归，覆盖缓存排除、用户数据导入、旧缓存保留、其他位置链接拒绝及错误提示分类。
- 已在本机复现 1.0.0 启动失败，用修正后的迁移代码导入实际旧数据，并确认已安装的 1.0.0 能正常启动、恢复工作区与标签；6 个核心数据文件的原始内容保持不变。
- 正式安装包由 CI 构建和签名，并在公开前执行隔离安装器升级／卸载及两套更新清单校验。
- 未执行物理串口、USB、外部 SSH 设备及 Linux/macOS 原生打包验证。

## 升级说明

- 能正常启动的 Windows 安装版可通过应用内更新升级。
- 如果 1.0.0 因迁移报错无法启动，请直接下载本版 NSIS 安装包覆盖安装，无需删除旧配置目录。
- 便携版下载 `DevPort_1.0.1_x64-portable.exe`，退出旧版后运行新文件。
- 首次迁移保留旧配置及运行时缓存作为备份；项目 Python 环境需要在新目录重新准备。已有 DevPort 配置不会被旧数据覆盖。
- `latest.json`、`devport-latest.json` 与 `.exe.sig` 用于更新校验，不应单独运行。
