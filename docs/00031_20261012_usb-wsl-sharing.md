# Windows USB 共享到 WSL

## 目标与边界

Remote Runner 在 Windows 上管理本机 USB 设备，优先将其转交给本机 WSL2，方便运行烧录、调试和 USB 串口程序。底层使用外部安装的 usbipd-win 5.x，不自行实现 USB/IP 驱动，不改变 SSH / Serial / WSL / Local 的运行目标模型。

USB 连接属于整个 WSL2 虚拟机，所有 WSL2 发行版都能访问；发行版选择用于启动和验证，不提供发行版隔离。连接期间 Windows 不能使用设备。Linux 驱动和 udev 权限仍由发行版负责。

## 第一阶段交互

- 文件菜单的设备管理区域增加「USB 共享…」；WSL 设备配置增加快捷入口。
- 独立对话框显示依赖、WSL2 发行版、设备名称、VID:PID、BUSID、共享状态、客户端 IP，以及已共享但拔出的设备。
- 支持刷新、连接到 WSL、断开、取消共享、验证；窗口打开时轮询，关闭后停止轮询。
- 连接：检查 WSL2 与服务 → 启动发行版并保持连接操作期间存活 → 必要时 UAC bind → attach → 读取真实状态。验证单独检查 Linux sysfs 可见性及当前用户对 USB 节点的读写权限。
- 断开保留共享配置；取消共享撤销持久配置，离线记录通过 persisted GUID 删除。对已连接设备先要求显式断开。
- 已连接但无法确认来源的设备只显示「客户端已连接」及 IP，不把 IP 非空误判为 WSL，也不自动抢占。
- 共享与取消共享按需 UAC 提权，主应用保持普通权限；取消 UAC 单独报告。
- 任务完成、切换目标、关闭窗口或退出应用不自动断开 USB。用户可以连续执行多个任务。

## 后端实现

新增 `src-tauri/src/usb/`，Tauri 暴露 `usb_snapshot`、`usb_connect`、`usb_disconnect`、`usb_unshare`、`usb_verify`。

- 从系统安装目录定位 usbipd.exe，使用绝对路径，禁止从工作区/PATH 加载同名程序。
- `usbipd state` 返回 JSON；不解析人类可读表格。按 InstanceId / PersistedGuid 标识设备，BUSID 只用作当前操作地址，操作前重新核对身份。
- Rust 验证所有身份、BUSID、GUID、发行版和用户输入。所有普通进程通过结构化 argv 调用；提权命令只有固定 bind/unbind 操作和严格格式参数。
- 通过 ShellExecuteExW 的 runas 启动本应用的受限 `--usb-elevated` 子进程，只接受 bind/unbind 和 base64 JSON 设备选择器；在 Tauri/single-instance 初始化前处理并退出。子进程在用户接受 UAC 后重新核对设备身份，再调用固定路径 usbipd.exe，避免 UAC 等待期间插拔导致 BUSID 指向另一台设备。等待退出码后重新枚举。
- 操作串行执行；连接、断开和取消共享再次核对最新状态，避免重复点击或过期 BUSID 操作另一个设备。
- 进程输出有大小上限，普通命令有超时并清理子进程。取消 UAC、服务未启动、依赖版本不支持、WSL1、设备拔出、外部占用均有稳定错误码。
- 连接期间保守阻止本应用新增串口 lease；已有任何串口 lease 时拒绝 USB 转交，避免无法可靠映射 USB 复合设备与 COM 口产生竞态。外部程序占用交由 usbipd 报错，不自动 force bind。
- WSL sysfs 验证脚本通过 stdin 交给 Python，不把 helper 源码放进命令行；不要求安装 lsusb。按 VID:PID 列出全部匹配节点；同型号多设备不承诺识别到特定物理设备。检测 USB 节点读写权限不能替代具体驱动或串口节点权限检查。

依赖缺失时提供官方安装指南及 `winget install --interactive --exact dorssel.usbipd-win` 命令，不自动安装驱动或修改防火墙。usbipd-win 安装器默认允许本地子网连接；界面明确提示共享可能被网络客户端访问，不能将 WSL 入口描述为仅 WSL 可访问。

## 后续阶段

1. 用户显式开启自动重连：管理 `--auto-attach` 生命周期和停止入口，处理 BUSID 变化、同型号多设备、固件切换 VID/PID；默认关闭。
2. Windows → 远端 Linux：复用共享管理，通过 SSH 执行目标 usbip 客户端，补充 sudo、内核、网络与防火墙诊断。SSH 管理连接不代表 USB/IP 数据天然经过 SSH。

## 验证与验收

自动化验证 JSON 兼容、离线设备、身份与参数校验、过期 BUSID、外部占用、串口互斥、进程输出上限和超时、前端异步刷新及操作状态。运行 Rust 格式检查及相关测试、前端测试/build、git diff --check。

本机探测已确认 usbipd-win 5.3.0 开发版本、JSON 枚举以及 Ubuntu-24.04 WSL2。真实 bind/attach/detach、UAC、USB 串口、udev 和烧录时重置需要用户明确选择的开发 USB 硬件联调；自动化不得抢占现有键盘、鼠标、摄像头或存储设备。

## 实施状态

第一阶段代码已完成：独立 USB 对话框、文件菜单及 WSL 配置入口、系统依赖/服务探测、WSL2 枚举、JSON 状态读取、受限 UAC 子进程、身份复核、串口互斥、连接/断开/取消共享、离线记录删除、sysfs 验证和中英文提示。

验证结果（2026-10-12）：

- 前端 `npm test`：114 项通过，含异步刷新竞态、UAC 取消恢复、设备变更后验证失效、窗口渲染与安装指南权限。
- `npm run build`：通过。
- Rust `cargo test --offline --all-targets`：178 项单元测试、8 项 SSH 集成测试通过；11 项环境相关测试默认忽略。
- 指定 `REMOTE_RUNNER_TEST_WSL=Ubuntu-24.04` 的 USB 只读集成测试通过：实际系统安装路径、服务、USB JSON、发行版注册信息和 Linux sysfs 脚本链路。
- 实际 debug 可执行文件的非法 `--usb-elevated` 请求在应用启动前被拒绝，不创建应用窗口。
- Rust 格式检查和 `git diff --check` 通过。

真实 UAC 接受/取消及 USB bind/attach/detach/unbind 尚未硬件验证。第一版依赖默认 Program Files 安装目录；自定义安装路径暂不支持。自动重连、远端 Linux 和应用级 USB 使用租约留到后续阶段。

只读集成测试命令（不会共享或转交 USB）：

```powershell
$env:REMOTE_RUNNER_TEST_WSL = 'Ubuntu-24.04'
cargo test --offline --lib usb::tests::installed_usb_and_wsl_probe_readonly -- --include-ignored
```

## 界面整理（2026-10-12）

对话框采用独立标题栏、可滚动内容和固定底栏。连接目标集中展示发行版与验证用户；设备行以名称、状态徽标和 VID:PID / BUS / 客户端信息组织，只展示当前状态适用的操作。已共享但未插入的记录默认折叠，长说明和诊断详情按需展开。初次加载不再提前显示安装命令。

样式与应用深色工作台保持一致，补齐依赖状态、空列表、操作进度、权限结果和窄窗口布局。使用实际 React 组件及模拟状态通过无头浏览器检查桌面、英文窄窗口、缺少依赖与操作中状态；该视觉验证不调用 USB 后端。
