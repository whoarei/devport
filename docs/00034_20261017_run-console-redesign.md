# 运行控制台与工作区脚本运行重构

日期：2026-10-17

状态：已实施（2026-10-18）。实现结构与验证范围见 [实施记录](00035_20261018_run-console-implementation.md)。

2026-10-19 后续调整：侧栏「运行历史」面板、菜单入口、导出与清空功能已移除。本文关于保留旧历史 UI 和导出的决定仅记录当时范围；控制台任务状态与日志、工作区「历史命令」继续保留，详见 [旧历史功能状态](00014_20260912_run-history-export.md)。

日常运行改为「设置目标设备和运行环境 → 工作区右键运行 → 控制台查看和控制任务」。控制台不再提供任意命令输入、入口选择和常驻参数表单。Python 脚本、Python 模块与 Bash 脚本共享运行生命周期；预置命令继续在运行控制台执行。

新的「历史命令」在工作区 `.runner` 中保存入口和参数，执行时使用当前设备、当前 Python 环境及其他当前运行设置。现有「运行历史」面板、记录格式和用途保持原样，两套数据相互独立。

## 已确定的范围

| 项目 | 本次决定 |
| --- | --- |
| 控制台命令输入 | 移除自由输入命令的运行入口；独立终端承担临时命令操作 |
| 预置命令 | 保留面板、配置和控制台执行方式，继续使用当前目标设备 |
| 工作区运行入口 | 支持 Bash 脚本、Python 脚本、Python 模块，以及带参数运行 |
| Python 环境 | 提供设备默认 Python 和应用管理的项目 Python 环境 |
| 已有环境与 Conda | 暂不支持用户选择已有 venv、任意解释器或 Conda 环境 |
| 项目环境依赖模型 | 仅支持已有 uv 锁定项目，读取 `.python-version`、`pyproject.toml` 和 `uv.lock` |
| Python 配置来源 | 版本、依赖和源码搜索路径继续读取项目文件，不迁入 `.runner` 或本机运行设置 |
| Bash 环境 | 使用目标设备的 Bash 和系统运行上下文，Python 环境选择不影响 Bash |
| 默认工作目录 | 执行端工作区根目录；高级设置可指定工作区内子目录 |
| 新历史命令 | 只保存执行入口和参数；不保存设备、Python 环境或其他运行设置 |
| 工作区状态 | 在源工作区根目录下新增 `.runner` |
| 现有运行历史 | 不重构、不迁移、不删除，也不作为新历史命令的数据源 |

本次范围不包括依赖包逐项管理界面、Poetry/Pipenv 适配、自动生成 uv.lock、容器运行，以及 PowerShell/批处理脚本类型的扩展。

## 界面职责

### 控制台顶部

```text
目标设备 [Ubuntu WSL ▾]   Python [项目环境 · 3.12.9 ▾]   [运行设置…]
任务 [tools/train.py ▾]   运行中                         [停止] [重新运行]
```

第一行设置后续运行使用的设备和 Python 环境。第二行选择当前查看的任务并控制其生命周期。空闲时显示「在工作区右键脚本运行」；已选任务显示入口、状态和本次实际执行环境的摘要。

环境选择器仅提供「设备默认 Python」与「项目 Python 环境」。选择项目环境后，从项目文件读取配置；缺失或不合法时显示原因，并提供打开配置文件的入口；已配置但尚未准备时显示「需要准备」。选择器一直可达，不依赖先选中某个 `.py` 文件。

Bash 或预置命令启动时，在任务摘要中展示实际 Bash 或命令 Shell，不把顶部 Python 选择显示为该任务的运行环境。Python 环境设置可以提前编辑，但只影响后续 Python 运行。

控制台保留原始输出、交互输入、停止、任务切换、清空显示和调整终端尺寸。串口保留合并输出且不可调整尺寸的现有约束。任务运行期间可以修改后续运行的配置，已经启动的任务继续使用自己的配置快照。

「重新运行」复用本会话任务的入口和参数，使用保存文件后、提交时整体捕获的当前设备、环境和其他设置。对于预置命令，它复用预置命令的执行内容和原有选项语义。

每个本会话任务单独保留源工作区身份，使用规范化后的 `WorkspaceRef`，包含来源设备与根目录；预置命令未使用工作区时记为 `None`。当前工作区必须与任务的源工作区一致，才允许重新运行。切换到不同工作区或关闭原工作区时，「重新运行」变灰，提示「当前工作区与任务工作区不一致，请切回原工作区」；两个工作区即使都有同名 `main.py` 也不能互相替代。双方均为 `None` 的预置命令不受此项限制。

执行入口在开始保存前和保存完成后均复查工作区身份及工作区切换代次，不能只依赖按钮置灰。工作区发生变化则中止本次启动，不自动切回、不把旧入口拼到新工作区。任务的源工作区身份只保存在会话内任务上下文，不写入新历史命令，也不扩充旧运行历史。重启应用后，仅凭旧运行历史记录不能启用重新运行；源工作区身份不可确定时同样禁用。

### 运行设置

设置入口同时显示工作区与当前目标设备，避免混淆源码所在位置和执行位置。

| 设置 | 默认值和作用域 | 保存位置 |
| --- | --- | --- |
| 目标设备 | 恢复该工作区上次有效选择；无记录时，设备工作区优先其宿主，本地工作区使用应用默认设备 | 本机应用设置 |
| Python 环境选择 | 每个工作区、每台目标设备分别记忆；新组合默认设备 Python | 本机应用设置 |
| 工作目录 | 工作区根目录，内部表示为 `.` | `.runner/config.json` |
| Python 源码搜索目录 | 读取 `[tool.remote-runner].python-path`，缺省为空；路径相对工作区根目录 | `pyproject.toml` |
| 项目 Python 版本 | 读取次版本或完整补丁版本请求，不在运行设置中另存一份 | `.python-version`，并校验 `pyproject.toml` 的 `requires-python` |
| 项目依赖 | 读取 uv 项目声明与锁定结果，不新增依赖来源选择 | `pyproject.toml`、`uv.lock` |
| 输出模式、超时、附加环境变量 | 默认沿用现有行为，按工作区在本机记忆；串口强制合并输出 | 本机应用设置 |
| Windows 本机 Bash 选择 | 非 Bash 设备运行 `.sh` 时可指定已检测到的本机 Bash | 本机应用设置，按目标设备保存 |

输出模式默认 PTY，超时默认 0，表示不限。附加环境变量属于本次运行设置，不写入历史命令。Python 的 PATH 等必要变量由环境解析器按本次选择生成，不修改应用全局环境。

运行设置只展示 Python 版本、uv 依赖摘要、锁文件状态和源码搜索路径及对应项目文件，提供「打开配置文件」「重新检查」；不提供覆盖这些值的独立输入框。修改仍在项目文件中完成，保存后重新读取。源码搜索路径对设备默认 Python 与项目 Python 都生效，Bash 与预置命令不读取这项 Python 配置。

本机设备绑定包含连接配置修订和目标身份。SSH 主机或用户、WSL 发行版或用户、本机 Shell/profile 配置发生变化后，旧环境探测结果失效。切换设备立即清除旧设备的解释器路径、版本和就绪提示，异步响应必须核对工作区、设备及配置修订。

设备工作区的源宿主连接修订也参与状态加载和过期响应检查。即使设备 ID 和工作区路径不变，修改源宿主连接后也重新读取 `.runner` 配置与历史，保留当前运行目标和本机偏好；旧连接的查询、保存及菜单回调不能覆盖或操作新连接的状态。

## 工作区右键运行

### 文件和目录菜单

| 右键对象 | 新增菜单 |
| --- | --- |
| `.py` 文件 | 运行、带参数运行…、作为 Python 模块运行…、历史命令 |
| `.sh` 文件 | 运行、带参数运行…、历史命令 |
| 含 `__main__.py` 的 Python 包目录 | 运行 Python 包、带参数运行 Python 包…、历史命令 |
| 工作区根或空白处 | 运行 Python 模块…、历史命令、运行设置… |

不自动执行刚刚选中的文件；运行对象取右键命中的文件或目录，与编辑器活动标签无关。脚本可以直接从未打开的文件运行，不依赖工具栏收集已加载脚本列表。

「运行」和「运行 Python 包」始终传入空参数，不隐式复用上次参数。没有目标设备时打开运行设置并提示选择；不启动临时默认目标。启动后自动展开控制台并切到对应任务。

「带参数运行…」打开轻量对话框，显示入口、当前设备和当前环境，只要求编辑脚本参数。可从该入口最近的历史命令预填参数，但预填不意味着执行。工作目录等设置统一从「运行设置」修改，参数对话框不另存一套隐藏设置。

### Python 模块和包

Python 的两种启动方式独立于环境类型：脚本执行使用 Python 加脚本路径，模块执行使用 Python 加 `-m` 与点分模块名。设备默认环境与项目环境都支持模块运行。

右键 `.py` 的「作为 Python 模块运行…」根据当前工作目录和源码搜索目录尝试推导模块名，在对话框中显示并允许修改；不能可靠推导时要求填写，不静默猜测。包目录必须能映射为可导入名称，且包含 `__main__.py`，才能直接「运行 Python 包」。

工作区根的「运行 Python 模块…」允许输入 `pytest` 等已安装模块名称及参数，不要求存在对应源码文件。通过文件或包发起的模块命令关联到该文件或目录；从根发起的模块命令可从工作区历史再次运行。

工作目录与源码搜索目录共同决定导入行为，不自动向环境安装工作区根项目。源码搜索路径从当前 `pyproject.toml` 读取，展开为执行端绝对路径，不烘焙进环境实例。Python `-m` 的语义见 [Python 命令行文档](https://docs.python.org/3/using/cmdline.html#cmdoption-m)。

### 参数编辑

参数在后端始终是 `Vec<String>`。前端使用逐项参数编辑：每项是一段原始字符串，支持空字符串、空格、引号、中文和 Windows 路径，提供最终 argv 预览。显示命令行仅供阅读，不再反向解析用于执行。

`a b` 作为一个参数输入时，实际传入一个参数；`$HOME`、`*`、`$(...)`、分号和重定向符号作为参数时按字面量传入。需要 Shell 展开或管道的操作继续通过终端或预置命令完成。当前 `argsText.split(/\s+/)` 必须移除。

## 新历史命令

### 与现有运行历史的区别

| 数据 | 内容 | 本次处理 |
| --- | --- | --- |
| 现有运行历史 | 每次执行的状态、设备名称、时间和日志信息 | 保持现有 UI、接口、存储与清理行为 |
| 新历史命令 | 可重复使用的入口与参数组合 | 新建工作区存储、右键菜单和管理接口 |

新历史命令不读取 `RunStatus.label` 来猜测入口或参数，不调用旧历史导出接口，也不因清空旧运行历史而被删除。旧运行历史现有的设备和环境字段保持原样；新历史命令不包含这些字段。

### 保存和执行规则

一条命令的可执行内容仅包括「入口类型、脚本路径或模块名、参数数组」。不保存目标设备、环境类型、环境 ID、解释器路径、工作目录、源码搜索目录、附加环境变量、超时或输出模式。

记录 ID、最近使用时间和模块来源关联属于索引元数据，不参与执行配置。脚本路径相对工作区根目录；模块名是点分名称。模块来源关联只决定在哪个右键菜单显示，不改变模块搜索路径。

进程成功创建后记入历史；业务代码随后报错或以非零状态退出的命令也保留。参数校验失败、保存失败、同步失败、环境准备失败或在进程启动前取消，不记为运行过。历史写入失败不终止已启动的进程，显示「任务已启动，历史命令未保存」并提供重试。

同一工作区内，以规范化后的 `entry + args` 生成稳定 ID，全工作区按该 ID 去重，不使用每次运行新生成的 UUID。重复执行只更新同一条记录的最近使用时间，不追加重复项；切换设备、环境或右键来源也不改变命令身份。普通无参数运行同样只有一条对应记录。

选择历史项时，将入口和参数与保存文件后、提交时整体捕获的当前运行设置合成新请求。例如在设备 A、项目 Python 环境运行的 `tools/train.py --epochs 10`，切到设备 B、设备默认 Python 后，直接用 B 的当前设置运行；工作目录和源码搜索路径也取当前值。

历史执行使用当前已保存的源码。模块或依赖在当前设备不可用时，报告本次真实错误，不恢复历史环境，也不自动切回原设备。

### 稳定 ID

ID 由 Rust 统一计算。先校验并规范化入口，再把下列固定顺序数组序列化为紧凑 JSON，以无 BOM 的 UTF-8 字节计算完整 SHA-256，保存为 64 位小写十六进制字符串：

```text
canonical = JSON(["runner-command-v1", entry.type, entry.path_or_name, args])
id = lowercase_hex(SHA256(UTF8(canonical)))
```

`entry.type` 必须参与计算，区分 Python 脚本、Python 模块与 Bash 脚本。脚本路径使用经过工作区边界校验的相对路径，分隔符统一为 `/`，拒绝 `.`、`..` 和空路径组件；模块使用经过校验的点分名称。路径和模块名不转小写，不根据执行设备改写身份，避免合并在其他平台上实际不同的入口。

参数使用原始字符串数组，不 trim、不排序、不拼成一段命令行，也不把 Shell 转义后的显示文本作为输入。JSON 数组保留参数边界，因此 `["a b"]` 与 `["a", "b"]`、`[]` 与 `[""]`、`["a", "b"]` 与 `["b", "a"]` 都产生不同 ID。固定数组结构不依赖对象键顺序；版本标识固定算法格式，schema 升级不能静默改变现有 ID 语义。

设备、Python 环境、cwd、源码搜索路径、时间及菜单来源均不参与 ID。工作区身份也不参与，因为 `commands.json` 已按源工作区隔离；复制工作区时同一命令保留相同 ID。

保存采用按 ID 插入或更新的方式：不存在则新增，已存在则保留一条记录、取最新使用时间，并合并模块来源关联。后端读取文件时重新计算并校验 ID，不能盲信文件或前端传入的值。文件中存在 UUID、错误 ID 或重复条目时，按内容在内存中重算合并，下次正常保存时写回；不读取或迁移旧「运行历史」。

### 菜单与维护

文件右键默认显示该文件最近 10 条不同命令，文本以参数摘要为主，模块项额外显示 `python -m` 和模块名；不显示历史设备或环境。没有记录时显示置灰占位。提供「管理历史命令…」查看完整参数和删除单条命令。工作区根菜单可查看和管理全部命令，暂不提供「清空当前对象」或其他批量清空操作。

文件和目录的历史管理页面只是工作区命令的筛选视图。「删除命令」始终按稳定 ID 删除该工作区中的整条记录，管理界面明确说明共享命令会从所有关联菜单移除；不将它包装成只删除当前来源的操作。首版不提供按来源解除关联或清空来源的接口，因此同一模块的多个 `sources` 不存在局部清理与全局删除混用的语义。

应用内重命名文件或目录成功后，更新历史中的脚本路径及模块来源关联。模块名只有在当前源码搜索设置下能够唯一重新推导时才更新，否则保留并标记需要编辑。历史更新失败不回滚已完成的文件操作。外部重命名不做名称猜测；删除的脚本记录保留为不可直接执行，可删除或修正。

脚本或模块入口修改后，按新入口和原参数重新计算 ID，移除旧 ID；新 ID 已存在时合并为一条，取最新使用时间并合并来源。仅修改模块菜单来源时 ID 不变。工作区目录整体移动后，相对入口与参数随 `.runner` 一起保留，ID 不变；本机设备绑定需要按新的工作区身份重新选择或恢复，不从历史猜测。

## 工作区状态目录

### 文件与归属

```text
<源工作区>/
  .runner/
    config.json       工作目录等运行默认设置
    commands.json     新历史命令
```

只在第一次保存设置或历史命令时创建目录，不因打开工作区就写入。已有 `.runner` 中的未知文件保留；同名文件内容或 schema 不合法时报告错误，不覆盖原数据。运行日志、下载缓存、Python 安装和实际隔离环境均不放入 `.runner`。

本地工作区把状态写在本地目录；设备工作区把状态写在源设备的工作区目录。跨设备运行的暂存目录和上传目录不是状态归属位置，任务结束后不能把状态写到已经清理的临时目录。

设备 ID、设备绝对路径、环境选择绑定、解释器探测结果以及附加环境变量继续保存在本机应用设置。`.runner/config.json` 只保存工作目录等运行默认设置；Python 版本、uv 项目依赖、groups/extras 和源码搜索路径保留在原项目文件，不在这里或本机应用设置中建立另一份配置。

### 配置示例

```json
{
  "schema": 1,
  "run_defaults": {
    "cwd": "."
  }
}
```

无配置时工作目录为根。`config.json` 不定义 `python_project`、`python_version`、`dependencies` 或 `python_path` 字段，不能覆盖项目文件中的 Python 配置。内部环境配方由项目文件即时解析生成；首版每个工作区维护一套文件配置，在不同设备分别准备实例，不增加多配方管理界面。

### 历史命令示例

```json
{
```

### 读写和限额

通过 Rust 的工作区元数据服务访问固定文件名，前端不传入任意目标状态文件路径。读取和写入均复用工作区根约束：逐组件拒绝符号链接、Windows 重解析点和越界路径；WSL 使用 dirfd 与 `O_NOFOLLOW`，SSH 使用逐级 `symlink_metadata`。

新增元数据访问能力不依赖文件树是否显示隐藏目录，也不能通过放宽普通工作区读写的路径校验来实现。远端可复用文件服务协议和校验函数，运行发起的状态写入使用独立连接，不占用编辑长连接。

首版 `commands.json` 上限 1 MiB、全工作区最多 200 条不同命令，按稳定 ID 计数；菜单来源只用于筛选，不额外分配命令记录。`config.json` 上限 256 KiB。单次请求继续受现有 64 KiB 限额约束。参数和状态按普通工作区文件保存，不自动修改项目 Git 忽略配置。

读取现有磁盘文件时，文件字节数超限、schema 不支持或结构损坏，只报告错误并保留原文件，不以淘汰或截断来修复外部数据。正常插入或更新产生的候选文件，按以下规则在写入前控制容量：

1. 按稳定 ID 完成合并，保留本次新建或更新的命令，计算整个候选 JSON 按实际落盘格式序列化后的 UTF-8 字节数；计入外层结构、缩进、转义、时间和 `sources`，不能只统计参数字符数。
2. 条数超过 200 或文件超过 1 MiB 时，按最近使用时间从旧到新整条淘汰其他命令；时间相同时按 ID 升序排序。每次淘汰后重新计算，直到两项限制同时满足，再安全替换原文件。
3. 若只剩本次命令及文件外层结构仍超过 1 MiB，拒绝这次历史保存并保留原文件，报告「命令记录过大，未保存历史」；已经启动的运行继续。不截断参数或来源，也不先把其他记录从磁盘删除。

因此，较长参数即使在不足 200 条时触达字节上限，也能通过淘汰旧记录继续记忆本次命令。自动淘汰是存储容量策略，不对应用户可调用的批量清空功能。

写入流程为「读取 revision → 获取短写锁 → 复查 revision → 合并或修改 → 临时文件写入 → 安全替换」。锁按源工作区区分；同一进程串行化写操作，跨进程使用排他创建或原子创建锁目录。释放锁必须核对拥有者，崩溃残留锁应报告并提供明确修复入口，不静默强占。

历史插入或更新遇到 revision 冲突时，重新读取并按稳定 ID 合并，同 ID 取最新使用时间、来源取去重并集，最多重试 3 次；用户删除或编辑历史遇到冲突时要求刷新，不能把已删除项从旧快照复活。配置编辑冲突直接报告，不静默覆盖。

本机与 WSL 使用可安全替换旧文件的接口；SSH 优先使用支持覆盖的原子 rename 能力。若服务端不支持安全替换，保留原文件并报告保存失败，不沿用普通编辑器「先删除旧文件再 rename」的退化路径。只读工作区、连接中断或状态文件损坏均不阻断原本可执行的运行，但配置未保存时必须明确展示本会话生效状态。

## Python 环境

### 两种选择

| 选择 | 解释器 | 依赖和生命周期 |
| --- | --- | --- |
| 设备默认 Python | 在所选目标设备的执行上下文解析，展示实际路径和版本 | 用户维护；应用不向其中自动安装依赖 |
| 项目 Python 环境 | 应用在目标设备管理目录安装固定版本 Python 并建立隔离环境 | 应用按项目配方准备、复用、重新准备和删除 |

「设备默认」表示设备配置所决定的 Shell/profile 和 PATH 上下文中的 Python，不保证一定是 `/usr/bin/python3`。本机 Python 解析应与所选 Shell 的 profile 策略一致，拿到解释器后按绝对路径启动，不能继续直接用 Tauri 进程 PATH 代替设备运行上下文。

本机直接启动时沿用探测所得的完整环境，包含 profile 设置或删除的变量；显式运行变量在 profile 后应用。此环境仅供后端启动使用，不写入历史命令，Python 环境选择仍不影响 Bash 的执行环境。

本机探测使用受控临时脚本传递附加环境变量，不把变量值拼入 Shell 命令行；保留原始字符、换行和 profile 后覆盖语义。Windows PowerShell 5.1 的 .NET 环境变量接口会删除空值，因此显式空值通过 Windows 原生接口设置，Python 启动钩子和业务进程都应看到空字符串。取消或超时终止探测的进程树并等待退出，丢弃准备 future 时也清理其子进程。临时脚本在探测结束时清理。

应用终端中临时执行 `activate`、修改 PATH 或 `cd`，不会反向改变运行控制台的上下文。设备默认 Python 每次运行重新校验；路径或版本变化在本次摘要中显示。找不到 Python 时允许用户配置项目环境，不静默下载、改用另一设备或选择任意已有环境。

项目环境不暴露用户自定义激活命令或任意解释器路径输入。应用内部创建隔离环境可以使用 venv 机制；这与支持用户选择已有 venv 是不同范围。继续复用现有 Runtime Catalog、uv 版本与下载校验、managed-only Python 和目录隔离约束。运行阶段直接启动已验证的环境解释器，不使用激活脚本，也不通过 `uv run` 再次决定依赖或入口。标准隔离环境的解释器调用方式见 [Python venv 文档](https://docs.python.org/3/library/venv.html#how-venvs-work)。

### 项目配置来源

Python 项目文件继续作为配置来源，运行设置不复制或覆盖其中的值。

| 内容 | 配置来源 | 读取规则 |
| --- | --- | --- |
| 项目环境的 Python 版本 | `.python-version` | 支持单个 CPython 次版本或完整补丁版本，例如 `3.12` 或 `3.12.9`；缺失时提示补齐 |
| Python 版本兼容约束 | `pyproject.toml` 的 `[project].requires-python` | 项目环境保留必需字段要求，检查请求范围是否兼容及实际解析版本是否满足；不能反过来覆盖 `.python-version` |
| uv 项目依赖和锁定结果 | `pyproject.toml` 与 `uv.lock` | 保留已有声明和锁定同步语义 |
| 源码搜索目录 | `pyproject.toml` 的 `[tool.remote-runner].python-path` | 保留现有字段；缺省为空，所有目录相对工作区根校验 |
| uv groups 和 extras | `[tool.remote-runner].dependency-groups` 与 `.extras` | 保留现有字段和声明校验 |

`.python-version` 是项目 Python 请求的唯一来源，界面不另存一份。`3.12` 由 uv 结合 `requires-python` 在同一次版本中选择可用受管解释器；`3.12.9` 则固定补丁版本。实际版本及 build 进入环境身份，`uv sync` 显式使用本次解析出的解释器绝对路径，声明文件不会被改写。新的准备若解析到不同补丁版本，会使用不同实例，既有实例保持原路径。设备默认 Python 仍使用目标设备实际解析出的解释器，项目版本文件不会使它自动下载或改用托管 Python；界面分别显示实际版本和项目声明。

设备默认 Python 不要求存在 `.python-version` 或 `uv.lock`。不存在 pyproject 或源码搜索字段时按 Python 默认搜索行为运行；存在 `python-path` 时仍读取、校验并应用。项目环境必须具备 `.python-version`、`pyproject.toml` 和 `uv.lock`，不把这套三文件要求强加给系统 Python。

### 项目配方和准备

项目环境只支持已有 uv 锁定项目，不提供独立的「无依赖」环境模式或 requirements 安装模式，不新增 `dependency-source`、requirements 路径等配置字段。界面只有检查、准备和维护操作，不再提供依赖来源选择。

```toml
[tool.remote-runner]
python-path = ["src"]
dependency-groups = []
extras = []
```

准备前检查三个项目文件、`[project].name`、`requires-python`、Python 版本请求及选中的 groups/extras；次版本请求不能被当成补丁 `.0` 检查。uv 解析后再次校验实际完整版本，使用 `uv sync --locked --python <已解析的解释器绝对路径>` 同步到目标设备的应用管理环境，不生成或更新源锁文件。缺少文件、锁过期或约束不满足时，指出对应文件和原因，用户可补齐配置或显式切换设备默认 Python，不自动采用其他依赖模型。

即使合法 uv 项目的依赖列表为空，也仍走相同的三文件校验和锁定同步流程，不增加跳过锁文件的空环境分支。项目中其他依赖清单不参与托管准备，也不改变 uv 依赖输入。锁定同步语义见 [uv 文档](https://docs.astral.sh/uv/concepts/projects/sync/)。

`[tool.remote-runner]` 不必包含入口配置：其中的 `entry`、`mode` 不参与环境准备，也不能覆盖右键入口。没有该表时，源码搜索目录、groups/extras 使用缺省值；只解耦入口要求，保留现有项目字段的位置和含义。包源和网络凭据经既有项目配置及独立应用配置处理，不写进历史命令。

uv 项目继续沿用现有不安装根项目及本地 path dependency、uv workspace、editable 等限制。`src` 布局通过当前源码搜索设置加载；不为这次交互重构扩大项目安装范围。

### 环境复用与维护

应用管理的 Python、环境目录、manifest 和缓存位于执行设备的专用管理根。源码、入口、参数、工作目录和源码搜索路径不参与依赖环境身份；uv 项目输入与锁摘要、精确 Python/build、uv 版本、平台、groups/extras 和包源身份参与。

只修改业务代码时复用现有实例。依赖或 Python 配方变化时显示「需要准备」，后续运行显式进入准备步骤；失败时保留原实例，但不悄悄使用旧依赖启动当前配方。

环境必须在最终唯一目录创建，不能先生成 venv 再移动。准备完成并通过验证后写 ready marker，再切换当前绑定；重新准备创建新代次。绑定目录创建、临时文件写入或原子替换失败时，同样清理本次新实例，不能因已有 ready marker 而遗留；缓存命中的既有实例及旧绑定保留。所有使用同一实例的运行分别持有引用计数租约，最后一个任务结束后才释放保护。不得继续用无法区分多个使用者的单纯集合来代表占用。

实例从准备开始即受租约保护，准备结果将保护连续交接给运行阶段；失败和取消释放租约。租约登记与删除、清理的检查及删除操作互斥，尚未 ready 的活动实例也不得被缓存清理删除。

「Python 环境」管理界面从运行设置直接可达，复用现有 `runtime` 面板 ID，保留布局偏好。日常显示工作区名、设备、Python 版本和状态；环境 ID、uv 版本、摘要和目录放入详情。提供检查、准备、重新准备、删除未使用实例及清理缓存。

运行设置中的「准备环境」和「重建环境」直接在弹框内显示准备阶段、最新进度、最近日志和最终结果，并提供「取消准备」。提交后、成功或失败时均保持弹框打开，不自动切换当前任务、终端标签或主界面控制台；提交失败也在弹框内展示原因。准备仍复用后端 RunManager 的取消和资源清理语义，日志展示保留最近 64 KiB，原始日志存储不变。

准备日志记录带时间的阶段、目标平台与工作区、项目输入摘要、解释器解析结果、缓存复用或重建判断、关键命令的参数与工作目录、输出、退出码、耗时和失败清理结果；生成的诊断信息隐藏 URL 凭据，不输出附加环境变量值。失败时保留最后阶段和完整错误原因。输入冲突同时给出文件名、预期/实际 SHA-256、校验目标和工作区，便于区分源文件修改与传输差异。SSH/WSL 上传根目录的 `.python-version`、`pyproject.toml`、`uv.lock` 时保持原始字节，与规划快照严格一致；串口仍按既有 LF 文本上传规则校验。

用户主动关闭弹框后，准备任务在后台继续；再次打开仍能查看同一任务的进度和结果。准备期间禁用重复准备和重建，取消按钮始终作用于该准备任务。结果明确显示提交快照中的工作区与目标设备，结束时仅在源工作区、源连接修订、当前目标及其修订都匹配时刷新环境提示，避免旧任务覆盖新的选择。正常脚本运行继续按原规则显示运行控制台。

已有应用管理实例先检查兼容性，验证通过后复用，不因界面改名强制重装。用户现有 venv 或 Conda 不作为候选，不自动扫描、接管或删除。

## Bash 与预置命令

Bash 脚本始终由目标设备上已解析的 Bash 执行。Python 环境选择不改变 Bash 的 PATH、`VIRTUAL_ENV`、`PYTHONHOME` 或脚本内部调用 `python` 时的解析结果。通用附加环境变量仍属于用户当前运行设置，按原有规则应用。

Linux、SSH 和 WSL 路径在目标端解析 Bash，缺失时报告原因，不把 Bash 脚本静默交给 `sh` 或 `zsh`。Windows 本机目标选择 Git Bash/MSYS2 Bash 时复用其配置；选择 pwsh、powershell、cmd 等非 Bash Shell 时，使用已检测并明确选定的本机 Bash。

本机存在一个有效候选时可直接采用；多个候选在设置中显示并记住选择。必须排除 `System32` 的旧 WSL `bash.exe` 启动器，不能把它作为本机 Bash。没有 Bash 时提示选择 Git Bash/MSYS2 或显式切换 WSL 目标，运行器不自动切设备。

Windows Bash 入口和 cwd 沿用现有 MSYS 路径转换、profile 与保留 cwd 规则。选定 Bash 使用自己的运行上下文，不把 PowerShell profile 源码交给 Bash。交给本机 Shell 的路径继续先经 `verbatim::simplify`，参数按数组传递。

预置命令继续使用所选目标设备的命令 Shell 和自身输出模式、超时设置，不使用 Python 项目环境，不写入新的脚本历史命令。保留 `ScriptKind::Command`、命令分发和 CLI 兼容入口；移除的是控制台的自由命令输入 UI。

## 工作区和设备组合

| 源工作区与执行目标 | 源码和 cwd | 项目环境 | 历史命令写入 |
| --- | --- | --- | --- |
| 本地工作区到本机 | 工作区原地执行 | 本机应用目录准备 | 本地源工作区 `.runner` |
| 本地工作区到 SSH 或 WSL | 沿用上传管线，在目标执行目录运行 | 目标设备准备 | 本地源工作区 `.runner` |
| 设备工作区到同设备 | 源工作区原地执行 | 在该设备准备，解除当前同设备禁用限制 | 源设备工作区 `.runner` |
| 设备工作区到另一设备 | 先暂存，再使用上传管线 | 目标设备准备 | 源设备工作区 `.runner` |
| 任意工作区到串口 | 保留 UTF-8 文本上传与 shell framing | 仅设备默认 Python，不支持创建项目环境 | 源工作区 `.runner` |

`.runner` 整个根级目录从运行上传、WSL 快照、串口预检和跨设备暂存中排除；过滤规则必须在限额统计之前统一生效。运行需要的配置先从源工作区解析为结构化快照，通过控制通道传给目标，不能在已排除 `.runner` 的目标副本中重新读取它。

用户主动使用文件传输复制整个工作区时，`.runner` 作为普通目录随用户选择传输；运行上传过滤不自动变成文件传输的排除规则，也不做双向状态合并。

环境不随源码复制。设备环境目录与其他设备不共享，venv 的不可搬移语义见 [Python venv 文档](https://docs.python.org/3/library/venv.html)。上传与暂存继续遵守既有大小、条目、路径与链接限制，临时目录仍须覆盖全部成功、失败和取消路径的清理。

同设备项目环境需要新增基于 `WorkspaceRef` 的配置检查器，在源设备有界读取依赖文件并复用原有路径校验，不能继续要求本机目录才能 inspect。串口没有额外文件或探测通道；端口忙时不得为了刷新 Python 状态插入探测命令，探测仍使用端口租约和 nonce marker。

WSL 的连接 helper 仍依赖发行版预装 Python 3.8+；项目环境不能替代该连接前提。保持 helper 经 stdin 下发、结构化进程参数、显式退出消息和进程组停止的现有协议。

## 后端模型与接口

以下为候选类型，实施时可调整命名，职责边界固定。

```rust
enum WorkspaceRunEntry {
    BashScript { path: String },
    PythonScript { path: String },
    PythonModule { name: String },
}

struct WorkspaceCommand {
    entry: WorkspaceRunEntry,
    args: Vec<String>,
}

enum PythonSelection {
    DeviceDefault,
    Project,
}

struct RunWorkspaceRequest {
    workspace: WorkspaceRef,
    device_id: String,
    device_revision: String,
    command: WorkspaceCommand,
    python: Option<PythonSelection>,
    settings: ExecutionSettings,
}
```

历史文件只保存 `WorkspaceCommand` 及索引元数据。`ExecutionSettings` 包含当前工作目录、附加环境变量、输出模式、尺寸和超时；Python 版本、依赖和源码搜索目录由后端从当前项目文件解析，不接受请求中的同名覆盖字段。完成脏文件保存并复查源工作区后，从同一份前端状态快照一次性复制目标设备、该设备的 Python 环境选择及运行设置，字段复制期间不执行异步操作；不在保存前单独捕获设备，再在保存后拼接另一份环境或设置。Bash 不消费 `python` 字段，预置命令继续经过独立的 command 请求。

后端统一生成不可变的运行计划，包含源工作区身份和文件 revision、目标配置修订、实际入口、参数、执行端 cwd、实际解释器或 Bash、环境实例及准备动作。前端摘要展示同一份计划，不自行猜测启动路径。设备读取接口返回后端生成的配置 revision，前端随同设备选择一并捕获并提交 `device_revision`；后端核对设备 ID 和该修订，复制对应设备配置，从保存后的项目文件解析环境配方，再冻结本次计划。配置修订已经不匹配时返回计划过期，不能重新查找另一台设备或拼入更新后的配置。此后修改界面设置只影响下次运行；准备期间仍须复查实际使用的依赖文件和执行目录，防止计划与源码输入不一致。

解释器解析和环境准备由公共 resolver 完成，transport 只消费最终 LaunchSpec。Local 使用程序路径、argv、cwd、env；WSL 使用结构化 helper 消息；SSH 与串口继续逐参数严格引用。客户端不能回填托管解释器路径等后端派生字段。

脚本路径始终相对执行端工作区根目录展开，与 `cwd` 分开处理。即使 cwd 指向子目录，也不能把脚本入口再相对该子目录拼接一次。cwd 为 `.` 或经过验证的工作区内相对目录；源码搜索路径同样以工作区根为基准。Python 模块名、参数、环境变量和总请求大小均由 Rust 校验。

| 新增或重构接口 | 职责 |
| --- | --- |
| 设备读取接口的配置修订元数据 | 返回与设备配置对应的 revision，供前端整体捕获及后端启动校验 |
| `read_runner_config` / `save_runner_config` | 读取与带 revision 保存工作目录等运行默认设置，不读写 Python 项目配置 |
| `list_workspace_commands` | 读取新历史，按文件、目录或工作区筛选 |
| `update_workspace_commands` | 编辑、按稳定 ID 全局删除单条命令；不提供批量清空或来源解绑，运行记忆由后端在启动成功时更新 |
| `probe_python_environment` | 目标设备默认解释器探测与当前项目实例检查 |
| `inspect_python_project` | 支持 WorkspaceRef，校验 uv 三文件并读取版本、锁定依赖与源码搜索目录，解耦入口校验 |
| `plan_workspace_run` / `run_workspace` | 合成当前配置、校验、准备和执行 |
| 项目环境准备与管理接口 | 沿用 uv 托管能力，适配解耦后的项目配置及取消、租约模型 |

历史 ID 的生成、校验、按内容合并及重命名重算统一在 Rust 命令存储层完成，前端只使用后端返回的 ID。接口不借用旧运行历史的数据或导出能力；运行日志仍由当前 RunManager 按既有规则处理。

## 启动和故障处理

统一流程如下：

1. 捕获用户右键的入口、参数、源工作区身份与工作区切换代次；重新运行时先核对任务工作区与当前工作区一致。此时不单独冻结目标设备。
2. 保存该工作区全部脏文件，任一失败则停止；保存后再次核对源工作区身份和切换代次，发生切换则中止。随后从同一份前端状态一次性捕获当前目标设备、设备配置修订、该设备的 Python 环境选择及全部运行设置，形成完整提交快照。
3. 后端核对目标配置修订，验证入口、模块名、cwd、参数和目标能力，从保存后的项目文件解析依赖输入并记录 revision，生成不可变计划。快照已经过期时报告重试，不把保存前后的设置混合执行。
4. 按原地或跨设备路径准备源码；排除 `.runner`，复用既有限额。
5. Python 解析当前解释器，必要时准备项目环境；Bash 解析实际 Bash。准备与运行处于同一可取消生命周期。
6. 准备结束后复查实际执行的依赖输入与目录，变化则作废计划，不启动旧计划；不因用户为下次运行修改选择器而改用新配置。
7. 按 LaunchSpec 启动进程，显示实际摘要，成功创建后向源工作区记忆入口与参数。
8. 原有输出、输入、resize、停止升级和退出处理继续工作；终态释放连接、环境租约和暂存目录。

同设备原地运行无法冻结所有外部源码修改；运行前仍沿用工作区互斥守卫，并复查用于环境准备的有界输入，不能宣称对外部编辑提供事务性源码快照。

保存期间如果用户从设备 A 切到 B，第 2 步取得的设备、环境选择和运行设置必须全部属于 B；快照形成后再切换选择器，则只影响后续运行。前端启动守卫与工作区切换代次检查必须覆盖右键、历史命令及重新运行入口。

| 情况 | 行为 |
| --- | --- |
| 当前设备或 Python 不可用 | 保留当前选择并展示具体原因，不根据历史切换设备或环境 |
| 已选项目环境不支持目标平台或串口 | 明确阻止该 Python 运行，允许用户显式改选设备默认环境 |
| uv 项目配置或锁文件已变化 | 标记待检查或需要准备；锁过期时要求先更新源锁文件，失败不静默运行旧实例 |
| 包或模块在当前设置下找不到 | 显示当前 cwd、源码搜索目录与解释器，供用户修改设置 |
| Bash 不存在 | 提示本机 Bash 或其他目标选择，不交给不兼容 Shell |
| `.runner` 不可写或历史保存失败 | 运行继续；给出状态保存失败和重试入口 |
| `.runner` schema 不支持或损坏 | 保留文件，展示修复入口；已存在的配置不能被静默当作默认值覆盖 |
| 重新运行时工作区不匹配 | 按钮置灰并提示切回原工作区；启动守卫再次校验，不执行新工作区中的同名入口 |
| 保存期间切换工作区或提交快照已过期 | 中止本次启动并报告重试；不自动切换源码来源或混用设备设置 |
| 用户取消准备 | 停止受控子进程，清理失败代次与临时资源，保留已有就绪实例 |
| 运行期间切换设备或工作区 | 当前任务继续使用原快照；状态记忆仍指向源工作区，新 UI 丢弃旧查询结果 |

`.runner` 的运行默认设置无法读取时，可在用户明确选择的本会话设置下运行，不影响单独从项目文件解析 Python 配置。Python 项目文件损坏时，阻止需要这些字段的运行或项目环境准备，并指出源文件；不能使用 `.runner` 或本机缓存中的另一份值替代。非必要历史读写失败不升级成运行失败。

## 验收与验证

### 用户行为

- 控制台没有自由命令输入和常驻入口参数表单，预置命令仍能在控制台执行。
- 保存文件期间从设备 A 切换到 B，最终提交的目标、环境选择和运行设置全部来自 B 的同一快照；提交后再切设备不影响本次计划。
- 任务属于工作区 A、当前打开工作区 B 或已关闭 A 时，重新运行按钮变灰；两个工作区都有同名脚本也不能执行 B 中的文件。保存期间切换工作区时启动守卫同样阻止执行。
- 右键未打开的 `.py` 和 `.sh` 可运行命中的文件；普通运行不携带上次参数。
- 参数中的空字符串、空格、引号、中文、反斜杠和 Shell 符号保持原值。
- 相同入口与参数执行多次，重开应用或切换设备、环境、模块来源后再执行，`commands.json` 中始终只有一条对应命令，ID 不变。
- 相同模块从不同文件或目录发起时，合并 `sources`，各菜单可找到同一记录；参数边界、顺序或入口类型不同则得到不同 ID。
- 新历史界面和 API 不提供清空当前对象、批量清空或来源解绑；单条「删除命令」明确作用于整条共享记录，删除后从所有关联菜单移除。
- 正常追加即使不足 200 条，只要候选文件超过 1 MiB，也会按最近使用时间整条淘汰旧记录，直到同时满足条数和字节限制；本次命令保留，已有外部超限文件仍报告错误而不自动改写。
- 脚本重命名后重新计算 ID 并合并已有目标记录；工作区整体移动和最近使用时间变化不改变 ID。
- 系统与项目 Python 都支持脚本及 `-m`；模块入口不被项目配置替换。
- 在设备 A 的项目环境执行后，切到设备 B 的设备默认 Python，从历史运行同一入口参数；cwd、源码搜索路径、env、超时和模式均取 B 当前设置。
- 修改当前 cwd，或保存 `pyproject.toml` 中新的 `python-path` 后，旧历史使用当前值；历史文件中没有这些设置、设备或环境字段。
- `.runner/config.json` 不保存 Python 版本、依赖或源码路径；版本、依赖、groups/extras 和源码路径始终读取当前项目文件，运行设置不存在第二套覆盖值。
- uv 项目继续使用原三文件；设备默认 Python 不要求这些文件齐全；项目环境的 `.python-version` 支持 `3.12` 和 `3.12.9`，缺失时提示补齐，不在界面另外保存版本。
- 切换 Python 环境后运行 Bash 和预置命令，其执行环境不受影响；pwsh 设备上的 `.sh` 使用有效 Bash。
- uv 项目可准备环境；改代码复用，改依赖先检查锁定结果并准备新实例，取消不损坏旧实例。
- 项目环境缺少任一必需文件时明确失败，不从 requirements 文件安装、不创建绕过锁定流程的空环境；设备默认 Python 仍可直接运行普通脚本。
- 本地、远端原地和跨设备的状态始终写回源 `.runner`；运行副本没有 `.runner`，主动文件传输仍可包含它。
- 旧运行历史和新历史命令的清理互不影响，旧历史 UI 和格式保持原样。

### 自动化与交付检查

前端覆盖右键目标与活动文件不同、结构化参数、模块入口、历史仅合并入口参数、重新运行的工作区匹配与禁用提示、保存前后工作区切换及设备设置快照一致性、共享命令的全局单条删除、设置持久化与切换时异步结果过期、串口能力及中英文。使用场景断言，不为纯样式增加镜像测试。

Rust 覆盖入口与 cwd 分离、脚本路径和模块校验、提交快照的目标配置修订、默认解释器上下文、Windows Bash 解析、各 transport 的参数保真、`.runner` 链接与路径逃逸、限额、排他写锁、revision 冲突、崩溃后恢复和源目录归属。命令存储覆盖稳定 ID 的固定向量、重复执行和重启后去重、不同参数边界、跨设备 ID 一致、模块来源合并、入口修改后重算，以及文件中 UUID/错误 ID 的修正；容量覆盖多字节和 JSON 转义后的实际字节数、条数与字节数双重淘汰、时间相同的确定性排序、单条记录无法容纳时保留原文件，以及读取外部超限文件不改写。环境覆盖 uv 三文件与项目字段校验、禁止第二套 Python 覆盖配置、锁过期与缺失、禁止自动切换依赖模型、依赖变化、同设备读取、并发准备、多个任务的租约计数、取消及安全发布实例。
