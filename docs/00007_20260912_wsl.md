# WSL 直接连接

WSL 是本机运行目标。Windows 桌面应用通过系统 `wsl.exe --distribution <name> [--user <user>] --cd ~ --exec python3 -I -u -c <bootstrap>` 启动内置辅助程序。没有网络端口、SSH 客户端、SSH 服务或认证步骤，不需要安装常驻服务。

辅助程序源码**不作为 `-c` 参数传递**：Windows 命令行上限为 32767 字符，脚本一旦变大 `CreateProcess` 就会以 `os error 206`（文件名或扩展名太长）失败，而错误信息会被包装成「没有安装发行版」。实际做法是命令行只带一段极短的引导程序（约 150 字符），它从 stdin 首行读取 base64 编码的完整 helper 源码并 `exec`；收到的第一个协议消息只会在这次加载之后产生，因此握手可以确认脚本已就绪。命令行长度与脚本大小从此无关。

## 配置与依赖

新增 `transport: "wsl"` 和可选字段 `wsl: { distribution, user }`。旧 SSH、串口 JSON 配置保持兼容。发行版必填；用户为空使用发行版默认用户。发行版列表由 `wsl --list --quiet` 枚举，兼容 UTF-16LE 与 UTF-8 输出；未安装 WSL、发行版无效、用户无效、Python 缺失及启动超时均返回错误。

客户端限 Windows；WSL 内需要 Python 3.8+ 和 `/bin/sh`，Shell 脚本另需 `bash`。Python 使用隔离模式加载标准库。Python 辅助程序本身不读取登录 shell 初始化文件；命令默认不激活虚拟环境。可在命令中显式激活需要的环境。

## 工作区

- 运行前在 Rust 中读取并校验本地快照，单文件 16 MiB、总计 64 MiB、最多 4096 个文件/目录，路径最长 1024 字节，禁止控制字符。
- 拒绝符号链接、特殊文件及解析到其他目录的重定向路径；跳过 `.git`、`.hg`、`.svn`。
- 支持二进制和空目录。文本扩展名的 UTF-8 无 NUL 内容按现有 SSH 规则将 CRLF 转 LF；二进制保持原始字节。
- 从 2026-10-19 起，同一来源复用 `<workspace_root>/<工作区目录名>/workspace`，通过隐藏来源身份拒绝不同来源的同名冲突，通过独立 `tf_*` 文件会话比对 SHA-256、增量上传/删除，再由运行 helper 原地执行。旧的独占新目录上传协议仍供一次性管理工作区使用。目录描述符与 `O_NOFOLLOW` 继续约束所有路径；文件操作使用结构化消息。目录锁、产物保留、冲突和恢复规则见 `00036_20261019_incremental-workspace-sync.md`。
- 内容按 48 KiB 分块，以 base64 JSON 消息传输，每块确认后继续。工作区传输与程序 stdin 分离。
- Unix 来源保留普通权限位；Windows 来源 `.sh` 使用 0700，其余文件使用 0600（不保留 Windows ACL）。不自动删除运行目录或下载运行产物，失败或取消同步后可能留下部分快照。
- 未选择工作区时不创建运行目录，命令在所选 Linux 用户的主目录运行。

## 独立文件传输

2026-10-13 新增「文件 → 文件传输」入口，支持本机与发行版间双向普通文件 / 目录复制。传输使用独立 helper 会话和 `tf_*` 消息，原样保留二进制与换行，单文件 2 GiB、单批 10 GiB、10,000 条目；这些限制不改变以上运行快照和编辑器限制。

完整 helper 仍经 stdin 下发，命令行只携带短 bootstrap；`tf_*` 的文件内容按 32 KiB 有界分块确认。文件操作沿用目录描述符与 `O_NOFOLLOW`，临时文件写完后提交；取消或 EOF 尽力清理本会话未提交项，不终止整个发行版。配置、同名冲突、历史恢复和已知边界见 `00033_20261012_file-transfer-plan.md`。

## 执行与生命周期

PTY 使用 Linux 内的真实伪终端，支持 stdin、合并 stdout/stderr、初始大小和运行中缩放；pipe 模式独立传递 stdout/stderr。输出在辅助协议和前端事件边界均使用 base64，程序无法以原始输出伪造协议完成消息。

辅助程序在独立进程组中启动任务。停止按钮或运行超时会清空待写输入，并按 SIGINT → 3 秒 → SIGTERM → 3 秒 → SIGKILL 升级。控制台 Ctrl+C 使用独立 `interrupt` 控制消息：PTY 写入 `0x03`，pipe 向进程组发送一次 SIGINT；不设置停止原因或升级计时，允许程序捕获中断后继续运行和接收输入。正常退出也清理同组后代，防止后台子进程持有输出管道而使任务永不结束。结束前排空输出，并以明确退出码、停止原因更新既有运行历史。控制管道 EOF 时执行进程组清理；单纯进程断连不能被判定为成功。

主动创建新会话或脱离任务进程组的后台进程不在管理范围。此实现不提供跨会话恢复、守护进程托管、发行版关闭/重启、自动安装 Python、运行产物同步或对另一台电脑内的 WSL 的连接。

## Windows USB 设备

文件菜单设备管理区域的「USB 共享…」窗口和 WSL 设备配置快捷入口可管理本机 USB → WSL2。此功能额外依赖系统安装目录中的 usbipd-win 5.x 和 USBIP Device Host 服务；首次共享与取消共享按需 UAC 提权，普通 WSL 运行仍不依赖它。

USB 对所有 WSL2 发行版可见，所选发行版用于启动和验证。连接期间 Windows 不可使用设备；任务结束或关闭窗口不自动断开。USB 节点权限与驱动由发行版负责，验证按 VID:PID 列出全部匹配节点。默认防火墙规则还允许本地子网访问已共享设备。

设计、边界与验证见 `00031_20261012_usb-wsl-sharing.md`。USB 管理窗口还支持选择已保存的 SSH Linux 目标，见 `00032_20261012_usb-remote-linux.md`；当前仍需手动连接，暂不自动重连。

## 验证

默认 Rust 测试验证配置兼容、参数限制、发行版输出解码、文件快照和大小限制；Windows 默认跳过需要发行版的测试。使用 `REMOTE_RUNNER_TEST_WSL` 明确选择发行版并加 `--include-ignored` 可运行真实 WSL 的多帧二进制输出、非零退出码、PTY 输入与缩放、分级停止与超时、分块工作区上传、目标链接拒绝、异常 EOF、断连清理、启动前取消和 RunManager 历史持久化测试。Linux 下辅助协议测试直接使用本地 Python，不模拟 WSL 启动器。

本项目禁止 Computer Use；验证通过命令行和自动化测试完成。
