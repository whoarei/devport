# 工作区运行与控制台重构实施记录

日期：2026-10-18

对应设计：[00034 运行控制台重构](00034_20261017_run-console-redesign.md)。

## 已实现

- 控制台顶部保留目标设备、Python 环境、运行设置、任务切换、停止和重新运行。预置命令继续使用原执行接口，旧运行历史的 UI、存储和导出不变。
- 工作区右键支持 Python/Bash 脚本、逐项参数、Python 模块、含 `__main__.py` 且可唯一推导名称的包；入口取右键对象。无参数运行始终使用空数组。
- 新增工作区命令存储 `.runner/commands.json` 和工作目录设置 `.runner/config.json`。读取懒创建，源工作区持有状态；运行暂存及上传在计入限额前排除根级 `.runner`，独立文件传输不受影响。
- 命令按完整 SHA-256 固定数组算法去重，读取时修正 UUID/错误 ID，合并来源与时间。200 条与实际 UTF-8 JSON 1 MiB 双限额，淘汰整条最旧记录；外部超限、损坏或未知 schema 的文件保留并报错。
- 历史支持来源筛选、原始参数预览、单条全局删除和入口编辑。入口变更重算 ID 并合并目标项；没有清空当前对象或批量清空入口。重命名不能唯一推导的模块保留名称并设置可选索引标记 `needs_edit`，要求确认或编辑；该标记不参与命令 ID 和执行参数。
- 元数据读写复用文件传输 Host 的本机/SFTP/WSL 安全路径服务，使用排他写锁、内容 revision、临时文件和原子发布；检查 revision 到发布期间再次核对源文件，错误不降级为删除后写入。设置支持用户显式选择本会话值，遗留锁的恢复需要再次核对所有者 revision。
- 系统 Python 和 uv 项目环境均支持脚本与 `-m`。版本、依赖、groups/extras、源码搜索路径继续读取原项目文件，新运行不要求旧专用入口配置，也不被旧入口覆盖。旧入口可作为可见候选采用，不会提前写成历史。
- 本机 Python 在设备 Shell/profile 上下文解析，再以实际绝对解释器启动。Bash 独立解析，Windows 非 Bash 设备可选择 Git Bash/MSYS2；使用受控临时脚本传递 argv，避免 MSYS 与 Windows CRT 对双引号解析不同。临时脚本随会话退出清理。
- 新运行及环境准备/重建共用 RunManager 生命周期和取消通道。同设备 SSH/WSL 的 uv 项目原地检查与准备可用；串口继续仅支持系统 Python/Bash。
- 环境租约为引用计数。配方 ID 仍由既有算法生成，`bindings/<recipe-id>.json` 指向当前实例；首次有效缓存可复用原目录，重建创建新实例并在就绪后发布绑定，不移动或删除活动实例。失败/取消清理本次未发布的实例。
- 保存全部脏文件后同步捕获设备、修订、环境与所有设置；后端核对设备修订及工作区配置 revision，复查环境输入。任务会话上下文记录源工作区与实际启动摘要；工作区不匹配或来源未知时重新运行禁用，提交入口也复查工作区代次。

## 代码入口

2026-10-19 调整运行控制台中断语义：Ctrl+C 无选区时只发送一次 `0x03`，键盘长按重复事件不重复发送；有选区时保留复制。后端将该输入转换为单次 `SessionControl::Interrupt`，不设置取消标志或 stopping 状态。停止按钮继续调用 `stop_run`，通过独立 `SessionControl::Stop` 执行既有升级流程。SSH pipe 根据实际 PID 标记向进程组发送一次 SIGINT（早于 PID 的中断等待标记），PTY 透传终端中断；WSL 使用独立 helper 消息，串口保留 nonce 完成协议。本机 Windows pipe 不支持单次中断，明确报错并保留任务运行，需使用 PTY 或停止按钮。

此次验证：前端 172 项、Rust 库测试 229 项及 loopback 集成测试 18 项通过；19 项 opt-in 默认忽略，其中 WSL 相关 25 项（含普通及 opt-in 用例）已在 Ubuntu-24.04 显式运行通过。回归覆盖捕获中断后等待超过原停止升级期限、继续输入与正常退出、SSH PID 标记延迟、串口不启动停止倒计时，以及既有停止/超时升级。前端构建、Rust 格式及差异空白检查通过。运行中的开发版占用默认输出文件，全量 Rust 验证使用独立 `target/ctrl-c-check` 构建目录；未执行 SSH 真机或物理串口验证。Windows CPython 3.12 控制台输入的时序边界见 `00024_20260913_local-shell-implementation.md`。

前端由 `workspaceRunStore.ts` 管理设置、快照和会话摘要，`workspaceRunMenu.ts` 组装右键入口，`WorkspaceRunDialogs.tsx` 提供设置、参数和历史对话框。新 IPC 位于 `workspace_commands.rs`；模型、安全状态存储和项目输入读取位于 `workspace_run.rs`，解释器探测位于 `workspace_probe.rs`。

环境缓存提示只表示匹配版本、锁和 groups/extras 的就绪缓存存在；实际执行前仍校验 manifest、解释器与输入，不保证外部更改后的缓存可直接复用。

## 后续四项审核修复

- 串口系统 Python 校验使用规划阶段计算的 LF 文本哈希，与串口上传的换行规范一致。其他传输仍比较原始内容哈希；不能通过重新计算上传快照的哈希绕过规划后发生的内容变化。Store/上传联合回归及 duplex 完整执行回归覆盖 CRLF 正常运行和元数据变化拒绝。
- 环境实例在检查或创建前获取 lease，准备结果持有 lease 至交接运行；失败和取消自动释放。lease 登记与清理/删除的检查及删除操作互斥，避免检查后创建实例的竞态，等待清理锁时仍可取消。回归暂停在已创建但未 ready 的阶段，验证删除、缓存清理、成功交接和失败/取消清理。

## 后续三项审核修复

- 本机 Python 探测在 Windows 使用专属 Job Object，先以挂起方式创建 Shell、加入 Job 后再恢复主线程，避免启动早期的子进程逃离保护；Unix 使用独立进程组。取消、超时及错误时终止整组并回收直接子进程，Windows 额外等待成员进程句柄退出，不能只以 Job 活动计数为零判断清理完成。future 被丢弃时由资源守卫终止后代；正常成功保留原有 profile 副作用语义。真实进程回归覆盖 PowerShell、cmd、Git Bash 下的取消，以及超时、丢弃 future 与 Python 孙进程清理。
- PowerShell 和 POSIX Shell 使用排他创建的临时脚本传递附加环境变量，命令行仅携带短路径，结束后清理文件。PowerShell 仍经 `-Command` 执行受控脚本内容，保持原执行策略语义；UTF-8 BOM 兼容 Windows PowerShell 5.1。MSYS 的文本模式会处理 CRLF，因此 POSIX 脚本中的 CR 使用表达式还原。回归覆盖已检测 Shell 的设备默认/指定准备解释器路径、约 39 KiB 的变量、引号、中文、emoji 和 CRLF 的保真。
- 工作区状态记录源宿主连接修订。源设备连接变化后重新加载配置与历史，保留当前目标及运行偏好；查询及修改回调同时核对源修订，菜单异步加载和旧菜单动作同样失效。回归覆盖源设备 ID/路径不变而连接变化、运行目标保持不变、旧成功/失败响应拒绝，以及下一次提交使用新 cwd/revision。

## 2026-10-19：环境准备诊断和 CRLF 项目输入校验

- 根因是 SSH/WSL 上传沿用文本 CRLF → LF 转换，而准备环境比较规划时的原始字节哈希；Windows 项目因此可能误报 `Project input changed: pyproject.toml`。根目录三个项目输入文件现在按原始字节上传，其他脚本和串口的既有换行规则保持不变。回归联合执行项目检查、两种上传策略和目标工作区校验，并确认真实修改仍被拒绝。截图中项目的 `pyproject.toml` 经只读检查确有 20 个 CRLF 换行。
- 阶段和进度同步进入准备日志，记录时间、源/目标路径、平台与 Runtime 根目录、输入哈希、请求/解析的 Python 版本、解释器路径、环境缓存判断、关键命令参数、工作目录、原始输出、退出码、耗时及失败清理。生成的诊断文字对 URL 凭据脱敏，不记录附加环境变量值。
