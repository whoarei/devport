# 本机 Shell 直连（local transport）

本机是本机运行目标的进一步推广：不经过 SSH、串口或 WSL，直接在本机以指定 shell（pwsh、powershell、cmd、msys2 bash、Git Bash，或 macOS/Linux 的 bash/zsh/sh）运行 Python、Shell 脚本及命令。没有网络端口、认证步骤或辅助程序；后端以结构化参数直接 spawn 本机进程，绝不把 shell 路径、文件内容或环境变量插值进命令行。

## 配置与依赖

新增 `transport: "local"` 和可选字段 `local: { shell, path?, no_profile? }`。`shell` 是后端注册表中的 shell id（`pwsh` / `powershell` / `cmd` / `msys2` / `gitbash` / `bash` / `zsh` / `sh`）；`path` 为可选的可执行文件绝对路径覆盖，留空时按注册表候选位置探测（PATH + 常见安装目录，如 `C:\Program Files\PowerShell\7\pwsh.exe`、`C:\msys64\usr\bin\bash.exe`、`C:\Program Files\Git\bin\bash.exe`）。Windows 的 PATH 探测排除 `System32\bash.exe`（WSL 启动器，非本机 shell）。旧 SSH、串口、WSL JSON 配置保持兼容。

`no_profile`（默认 `false`）是**唯一**的 PowerShell profile 开关，交互终端、命令、脚本与连接测试全部读它（`local::profile_args`）：默认加载 profile，置位后统一加 `-NoProfile`。默认加载的理由与 posix 的 `-l`/`-li` 一致——fnm、nvm、conda 这类工具只把 PATH 注入 profile（fnm 甚至给每个 shell 生成独立的多 shell 目录），注册表 PATH 里没有它们，因此 npm 全局命令、`node`、`npm` 只在此模式下可见；关掉开关则行为更可预测，但只有注册表 PATH 里的命令可用。对 cmd 无影响（cmd 没有 profile 概念）。设计取舍与一次真实故障的复盘见 `00030_20260917_local-shell-profile-path-analysis.md`。

`list_local_shells` 命令返回当前探测到的可用 shell 列表（id、显示名、解析后的路径），供前端输入建议使用；注册表内但未自动探测到的 shell 也可手动输入 id 并填写可执行路径。测试连接以所选 shell 打印版本信息。本机设备不使用 `workspace_root`，保存时跳过该校验。

## 工作区

本机目标**原地运行**：不上传、不复制快照，直接以本地工作区目录为子进程 cwd；未选择工作区的命令以及独立终端从本机用户目录启动。工作区面板的「在终端中打开」可以把独立终端落在工作区（子）目录（subdir 与工作区树同构，校验规则与目录列表一致）。msys2/gitbash 以登录 shell 启动时会注入 `CHERE_INVOKING=1`（与「Git Bash Here」同一约定），阻止其 /etc/profile 把 cwd 改成用户主目录。运行产物（临时文件、输出文件）直接写入用户工作区；Running 期间不阻塞工作区编辑（与 IDE 本地运行一致）。入口文件沿用既有的相对路径校验（拒绝越界、符号链接、NUL）。

交给 shell 的工作区路径（运行 cwd、终端 cwd、msys2 入口路径）一律是**常规形式**：路径校验继续用 `std::fs::canonicalize` 的产物，但回写运行请求和终端 cwd 前经 `verbatim::simplify` 去掉 Windows 的 `\\?\` 前缀（`\\?\UNC\srv\share` → `\\srv\share`；设备路径、超长路径、去掉前缀会改变含义的路径保持原样）。否则 PowerShell 提示符会显示成 `Microsoft.PowerShell.Core\FileSystem::\\?\D:\...`，MSYS2/Git Bash 的路径转换会拼出不存在的 `//?/D:/...`。

## 执行与生命周期

命令构造按 shell 风味分派（posix / powershell / cmd）：

| 类型 | posix（msys2/gitbash/bash/zsh/sh） | pwsh / powershell | cmd |
|---|---|---|---|
| Python | 直接 spawn `<python> -u <entry> <args>`（Windows 优先 `python`，其他平台优先 `python3`），不经 shell | 同左 | 同左 |
| Shell | `<shell> [-l] <entry> <args>`（msys2/gitbash 用 `-l` 获得完整 PATH） | `[-NoProfile] -File <entry> <args>` | `/C <entry> <args>` |
| Command | `<shell> [-l] -c <command>` | `[-NoProfile] -Command <command>` | `/C <command>` |
| 连接测试 | `<shell> [-l] -c <探测脚本>` | `[-NoProfile] -Command <探测脚本>` | `/C <探测脚本>` |
| 交互终端 | `<shell> -li`（非登录：`-i`） | `[-NoProfile]` | 无参数 |

`[-NoProfile]` 由 `local.no_profile` 决定（见「配置与依赖」），四个入口共用同一开关，不允许某个入口自行选择是否加载 profile。

环境变量通过进程环境块注入，不生成 `export` 前缀，天然规避 shell 注入。Python/Shell 类型 spawn 解释器本身，参数不经 shell 解释。

PTY 模式使用 `portable-pty`（Windows ConPTY / Unix openpty+forkpty）：合并 stdout/stderr 为单一输出流，支持 stdin、初始大小和运行中缩放；pipe 模式分离 stdout/stderr 独立传递。启动期间收到的 stdin 与 resize 会在会话就绪后按序送达。输出读取线程通过有界队列施加背压，避免高吞吐进程无限占用内存。capabilities 为 `{ pipe: true, resize: true }`。

停止升级在 transport 内实现，语义与其他 transport 的 INT → TERM → KILL 对齐：

- Interrupt：PTY 向主端写入 `0x03`（Unix 终端驱动转发 SIGINT 给前台进程组；ConPTY 合成 Ctrl+C）；pipe-Unix 向子进程所在进程组发 SIGINT；pipe-Windows 无等价语义，直接落到 Kill。
- Terminate：Unix 向进程组发 SIGTERM；Windows 与 Kill 相同。
- Kill：Windows 用系统 `taskkill.exe /PID <pid> /T /F` 杀整棵进程树；Unix 向进程组发 SIGKILL（pipe 模式 spawn 时 `setsid`，PTY 模式 forkpty 自带新会话，子进程 pid 即进程组 id）。

升级节奏与用户停止/超时路径复用 `RunManager::await_transport`：用户停止（含控制台 Ctrl+C）映射为 Interrupt，超时由 local 执行循环内的 deadline 触发，最终以明确退出码与停止原因更新既有运行历史。退出判定以子进程 `wait()` 返回为准；输出通道 EOF 不是成功信号，退出前排空残余输出。

独立终端标签复用同一 PTY 会话层，启动交互式登录 shell（posix `-li`、pwsh/powershell 按 `no_profile` 决定 `-NoProfile`、cmd 无参数）。工作目录默认是本机用户目录；从工作区面板打开时以指定的工作区（子）目录为 cwd（常规形式，见「工作区」），目录不存在则打开失败。

## 边界与限制

- 主动创建新会话/脱离进程组的后台进程不在管理范围；不提供跨会话恢复与守护进程托管。
- pipe-Windows 没有 Ctrl+C 等价物，Interrupt 立即升级为进程树终止。
- cmd 运行 Shell 类型脚本要求入口为 `.bat`/`.cmd`；PowerShell 设备要求入口为 `.ps1`。解释器是否匹配入口文件由用户负责，后端不做扩展名校验。
- Windows 进程树终止依赖系统 `taskkill.exe`（V1）；后续可替换为 Job Object。
- MSYS2/Git Bash 程序在 ConPTY 下的兼容性取决于 MSYS2 版本（较新版本原生支持）；异常时改用 pipe 模式。

## 验证

默认 Rust 测试覆盖 shell 注册表探测、配置校验、各 shell 风味 × 脚本类型的 argv 构造，并按本机实际可用的 shell 运行真实集成用例（echo 输出、退出码透传、stdin、超时、分级停止、PTY resize 与 Ctrl+C），shell 缺失时自动跳过，无任何硬件依赖。前端测试沿用 esbuild + `node --test` 模式。验证命令同 AGENTS.md：`cargo fmt --all -- --check`、`cargo test --offline --all-targets`、`npm test`、`npm run build`。
