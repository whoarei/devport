REMOTE RUNNER / 技术方案 / 00002
TECHNICAL ARCHITECTURE

统一运行语义，
保留通道边界。

以 Tauri 桌面应用为边界：React 管理交互与视图，Rust 校验输入并协调工作区、环境和进程，各传输实现自己的协议、文件访问与完成确认。

架构与设计决策当前源码 · 0.12.0更新于 2026-10-20

01 / DESIGN INTENT架构目标与系统边界

应用在用户桌面进程中管理设备配置、编辑会话、任务、终端和传输。远端 SSH 依赖现有服务，Serial 依赖已登录 Shell，WSL 使用按需启动的 Python helper，Local 直接创建本机子进程。当前没有统一常驻 Agent、后台作业服务或服务端数据库。

D01

语义统一，能力显式

入口、状态、字节输出和控制由上层统一；pipe、resize、中断、文件访问和 Runtime 通过能力与边界区分，不能伪装为所有通道一致支持。

D02

源、目标、实例分离

WorkspaceRef 标识源目录；目标设备决定执行环境；每次 run ID 标识生命周期；环境配方与具体实例支持独立复用和重建。

D03

校验与预算在 Rust

路径、设备、参数、协议与资源上限由后端约束；前端选择或本地存储不能成为可信安全边界。

D04

成功必须有协议证据

完成标记、显式退出消息、文件提交确认各自定义成功。断线、EOF、本地写成功或窗口关闭不能替代远端确认。

需求与交互由 产品方案 定义。本文描述现有结构及必须维持的不变量，不把最初设想的 Executor/Agent/容器层绘制为已经存在的模块。

02 / SYSTEM MAP分层与模块职责

代码域职责边界
lib.rs插件顺序、AppState、共享租约、服务与 IPC 注册single-instance 首先注册；同步 IPC 启动后台任务使用 Tauri runtime。
runner.rs / process.rs请求验证、运行调度、状态、控制、输出日志与历史协议专属处理留在通道模块。
workspace_run / workspace_commands结构化运行意图、源端元数据、输入快照、新 IPC 适配仍适配到 RunManager，无独立通用执行引擎。
workspace / remote_workspace / workspace_sync安全读写、长连接编辑、暂存、增量执行副本编辑、暂存与同步的限额和生命周期明确区分。
runtime/平台探测、uv、Python、环境准备、绑定、锁与租约transport 消费最终程序/argv/cwd/env，不自行猜环境。
file_transfer/ · usb/二进制复制队列 / USB 控制面独立于运行上传；USB 数据链路不自动经过 SSH。
work_environment / tray / update客户端恢复、生命周期与签名更新快照不恢复进程；更新门阻止新任务竞态。

03 / PRESENTATION & IPC前端组织与通信数据流

前端状态按应用、工作区运行、终端、传输和 USB 分域；纯逻辑模块负责布局归一化、命令身份辅助、输出预算、编辑文档和回放。面板元数据与懒加载组件映射分开，新增面板只扩展注册与映射，减少组件/布局循环引用。

主要 IPC 在 api.ts，文件传输在 transferApi.ts。工作区查询使用 WorkspaceRef，不在组件里拼 SSH/WSL 访问命令。所有新增 UI 文案走 t()；zh 资源为键源，en 编译期约束同键。

输出采用有界拉取

进程字节 → RunManager.emit_output → 16 KiB 分片 / Base64
 → broadcast(256) → drain_run_events(最多 64 事件)
 → 单飞行轮询(~33 ms) → store 字节缓冲 → xterm 回放

慢/隐藏 WebView 不堆积无限原生投递。落后时 resync 恢复状态并保留近期输出，缓冲缺口不能拼接半个编码序列。前端单 run 2 MiB、4096 块，总计 16 MiB；终端有独立读泵，等待 xterm 写回调再读下一批。

异步结果必须带上下文

配置/历史/目录/环境请求检查 epoch、工作区身份及源连接修订；编辑保存还检查标签 generation。保存后同步捕获设备与设置，后端核对 device/config revision。后台准备弹框仅更新匹配任务，不切换主控制台当前选择。

详见 客户端状态与恢复；源端 CAS 与命令存储见 工作区设计。

04 / EXECUTION LIFECYCLE运行模型、状态与控制

校验并冻结入口/argv、源与目标修订、当前设置和项目输入
准备执行位置原地或暂存/同步，必要时等待目录租约
解析并启动实际 Python/Bash、cwd/env，复查输入
运行与回收输出/控制、确认退出、历史及资源释放

工作区入口使用 run_workspace，三类结构化 Entry 与 argv；预置命令及 CLI 保留 run_script。prepare/rebuild 是同一生命周期的特殊 operation。工作区命令在成功启动后写回源端；历史失败给警告，不中断已启动脚本。

preparing → syncing → starting → running → exited
                     ↘ stopping → canceled
错误 / 超时 → failed

phase = 环境准备子阶段
waiting_workspace = 等待目录
workspace_sync = 路径与同步统计

非零正常退出仍为 exited 并保留 exit_code。独立终端和运行控制台由 terminalClipboard.ts 统一处理 Ctrl+C / Ctrl+V，两个全局开关默认开启并即时生效；默认有选区时 Ctrl+C 复制，关闭复制开关或无选区时只发送一次中断，不启动停止倒计时。Ctrl+Shift+C / V 始终复制粘贴，异步粘贴核对原会话或任务。Stop 取消准备或执行通道升级；超时最终失败。SSH/WSL/Local 一般为 INT→TERM→KILL，Windows Local pipe 无温和中断，停止强制结束树。Serial 等 nonce 结束标记，不能确认则报告未知状态。

通道执行和完成证据专属约束
SSHPTY/pipe、PID/进程组与退出消息SFTP；逐参数引用；认证连接按运行内 channel 复用，不借编辑会话。
SerialRS/US 包围的随机 nonce 开始/结束标记已登录 Shell、单合并流、文本上传、端口租约、无运行中 resize。
WSLwsl.exe + stdin 下发 Python helper；独立控制消息和显式完成Windows；预装 Python 3.8+；结构化 argv；不终止整个发行版。
Localportable-pty 或 pipe 子进程等待ConPTY DSR 后端应答；统一 profile；Shell 路径先 simplify；探测有进程组守卫。

stdin、resize、Interrupt、Stop、Terminate、Kill 的通道实现通过公共控制类型协调，不以能力名称推断支持。精确协议、时序、输入预算和兼容入口见 运行与传输协议。

05 / WORKSPACE DESIGN来源、编辑与持久执行副本

WorkspaceRef 将本机目录与设备目录建模为两个变体。设备来源只允许 SSH/WSL，根必须 canonical 且设备路径绝对无 dot component；根下拒绝链接。SFTP 逐组件 LSTAT，WSL 使用 dirfd + O_NOFOLLOW。本机编辑保留 revision/EOL/BOM，1 MiB UTF-8，写入做 CAS。

同设备 ID 或本机到本机原地运行；跨设备先在本机暂存并保留原始来源身份，清理覆盖全部终态。SSH/WSL 上传复用 <root>/<source-name>/workspace，串口保留每运行目录。跨设备到 Local 的产物随临时目录删除。

分开保存三种状态

位置所有者和职责
源 .runnercwd 默认值、入口参数历史、写锁；历史完整 SHA-256 ID；不保存 Python 项目配方。
目标 .sync来源认领、成功 manifest、pending 恢复记录、运行期 lease。
本机客户端配置同步客户端 UUID、UI 偏好、恢复草稿、设备和运行状态。

运行上传/暂存排除根 .runner；主动文件传输不排除。三份根 Python 输入在 SSH/WSL 保持原始字节，普通脚本可按上传策略规范 LF。

增量同步是有所有权的提交

来源键由客户端 UUID 和 canonical 原始 WorkspaceRef 派生，目录名不加哈希后缀。认领不覆盖，拒绝不同来源同名或未知非空目录。所有候选先预检，再发布 pending、逐文件提交、发布 manifest；只删除仍为已知版本的受管文件，保留未知产物，不提供整树回滚。

来源大小、mtime 和缓存规则未变时复用摘要；权限也未变且无 pending 时信任成功清单并跳过目标读取。因此目标单独变化可能不被发现，同长度保留 mtime 的来源改写也可能命中缓存。这是当前优化的明确边界。需检查的路径由 SSH/WSL 最多 16 条批量预检，SSH 不支持时回退 SFTP。

目录锁覆盖同步、环境准备、执行直到确认退出。断线且不能确认进程终止则保留锁，不按年龄接管。清单有界、临时文件精确登记、文件修改前复查，SSH 安全发布依赖扩展。算法和限额以 工作区与增量同步 为准。

06 / PYTHON RUNTIME配方寻址与不可搬移环境实例

设备默认 Python 与项目 Python 是两种显式策略。前者在目标上下文解析；Local 还捕获完整 Shell/profile 环境后直接 spawn。后者只接受 uv 三文件契约，用发布固定 Catalog 部署 uv 与 managed CPython，不回退系统解释器。

源项目输入哈希 → 目标 profile → uv 下载/回读校验
 → managed Python 解析与验证 → 配方锁 / 实例租约
 → 有效缓存 或 uv sync --locked --no-install-project
 → smoke test → manifest + .ready → bindings 发布
 → 直接运行环境 Python

配方 ID 包含 uv/平台、实际 Python/build、OS/arch/libc、lock、groups/extras 和包源，不含脚本源码。以 SHA-256 前 32 字符表示；具体实例可不同。重建在新最终路径创建，验证后切换绑定，活动实例不搬移不删除，避免绝对 shebang 失效。

共享 LeaseSet 引用计数在准备前获取并交接到运行，删除/清理与登记互斥；失败/取消清理未发布实例并保留旧绑定。输入在同步及发布关键阶段复查，不能靠重算目标哈希掩盖计划失效。

远端根为 ~/.remote-runner/runtime-v1，Local 为 <app_config_dir>/runtime-v1。当前 UI 使用 direct；mirror/offline Rust 类型不等于完整离线产品。平台资产列表不等于对应机器已验证。完整模型、项目示例及排障见 Python 运行环境。

07 / AUXILIARY SERVICES独立的文件传输与 USB 控制

文件传输：计划、队列、流式提交

TransferManager 独立持有预检计划、固定端点/配置、并发许可、取消和逐文件结果。32 KiB 分块不经 WebView，单文件 2 GiB、批量 10 GiB、10,000 条目；全局并发 2，单设备 1。编辑器限额和运行上传限额均不套用。

临时文件完整写入后发布，保留两份使用不覆盖硬链接，覆盖使用安全替换；缺少 SSH 扩展明确失败，不能先删原文件。提交检查点同步到 journal，确认丢失的结果标 unknown；取消保留已提交条目，重试只处理未完成项并建立尝试链。重启中断，不自动续传。

USB：管理链路与数据链路分开

Windows 后端固定定位 usbipd-win 5.x，JSON 枚举身份；bind/unbind 使用受限 UAC 子进程，操作前后重查设备。转交期间与应用串口 lease 互斥，不强占其他客户端。

WSL2 接入针对虚拟机；远程 Linux 经 SSH 启动受限 stdin helper 管理 usbip，数据由 Linux 直连 Windows IPv4:3240。detach 核对 host/port/BUSID 对应唯一端口，不执行全量断开；sudo -n 仅操作授权命令。没有自动安装、隧道或自动重连。

传输安全边界、残留/未知结果和 USB 依赖以 文件传输与 USB 为准。

08 / PERSISTENCE & LIFECYCLE状态存储与工作环境恢复

存储域代表数据设计约束
应用配置目录设备、known_hosts、200 条可见完成状态及运行配置快照、删除后保留 7 天的记录、2 MiB/run 日志、传输 journal运行快照在暂存/环境解析前捕获，含目标修订、原始参数和显式设置；日志与历史同步淘汰，删除记录在启动时及每分钟检查到期清理，保护活跃日志。各自持久化语义不同，不能统称事务存储。
本机 work-environment.json当前/最近工作区、文件视图、脏草稿、终端描述、窗口、传输选项version 1、32 MiB，有界读写、临时文件 sync_all 后替换；坏记录保留。
WebView localStorage布局/语言/主题/缩放、最近目录、预置命令、按工作区运行偏好防御性读取；含 env 的偏好不是密钥存储。
源/目标文件系统.runner、.sync、Runtime 实例按所有权、revision 和租约维护，不能随 UI 清空而删除。

恢复快照 500 ms 防抖串行写，真退出及更新前 flush。恢复优先活动文件，其他按需读取；草稿带原 revision，不自动写源文件。终端仅恢复未连接描述，不恢复命令/进程。运行输出、选中任务和进程不进入该快照。

窗口按当前显示器/DPI 约束，失联屏幕位置回收；最小化不恢复，静默自启动保持隐藏。关闭窗口到托盘，真退出通过统一未保存/传输/快照/终端流程。single-instance 首注册，更新门阻止运行/传输注册与安装竞态。

更新检查固定 GitHub 清单和下载身份，Tauri minisign 校验，安装版与 portable 分流；CI 稳定标签构建 draft，人工安装验收后公开。详见 状态与恢复、开发与发布。

09 / TRUST & FAILURE安全与故障边界

风险面当前约束剩余边界
路径 / 类型Rust 组件校验、canonical 根、链接拒绝；WSL dirfd/no-followSFTP 多步检查不是对恶意并发改路径的完整隔离。
命令 / argv结构化参数或逐参数引用；helper stdin；命令长度预算用户显式 Shell 命令本身就是可执行代码。
主机 / 凭据SSH 指纹 TOFU 后固定，损坏拒绝；uv hash 与 updater 签名首连自动信任；devices 密码明文，无系统钥匙串。
资源 / 输出大小/条目/深度、分块、单飞行、缓冲与超时预算超量输出可丢旧数据；日志不是无限归档。
提交 / 故障单文件发布、pending/journal、精确残留清理、租约没有整树回滚；断线可能是结果未知，不能自动重试覆盖。
快照 / 恢复坏记录保护、CAS、用户操作优先、终端显式重连防抖末尾可能丢失，不恢复进程或撤销栈。
USB / 权限设备身份复查、受限提权、精确 detach、非交互 sudoUSB/IP 数据无 SSH 加密；root 后代清理可能无法确认。

失败处理原则：保存失败保留草稿；输入变更使计划作废；非必要历史写入失败仅警告；未确认进程退出保留执行锁；未知文件提交先核对。不得为了展示成功而吞掉这些差异。

10 / VERIFICATION & CHANGE验证策略与演进原则

前端用 Node 测试纯逻辑与交互契约，生产构建做 TypeScript 和 Vite 检查；Rust 离线全目标覆盖验证、模拟协议、本机真实进程及 loopback SSH/SFTP。WSL 集成显式启用；物理串口和 USB 不作为普通测试依赖。模拟通过不能写成硬件验收。

涉及运行或串口时执行完整前端测试/构建、Rust fmt/全目标测试及 diff 检查。浏览器样例可验证交互和恢复，原生窗口、多屏、托盘、自启动、真实安装和硬件仍需独立验证。可重复命令见 开发、验证与发布。

扩展时保持这些约束

  • 新增通道先定义能力、完成证据、字节/控制协议、文件安全和清理语义，再接入统一生命周期；不靠提示符或 EOF 猜成功。
  • 新增运行时沿用项目输入、配方、实例和租约的分离，保持明确失败及输入复查，不回退另一依赖模型。
  • 新增面板通过注册表；新增持久化先定义 schema、预算、冲突和损坏处理，不继续把状态塞入单一主 store 或跨域文件。
  • 修改协议/限额时同步详细设计与主文档摘要，不再新增按日期累积的实施记录。候选方向见产品方案，尚未承诺实现时间。
