# 串口 Shell V1 实现记录（2026-09-08）

## 范围

当前实现对应设计文档的 `SerialShellExecutor`，不要求目标设备安装 Agent。它假设串口已经打开，并且远端已经进入 Linux shell；程序不会猜测或自动发送用户名、密码，也不会把登录提示符当作可执行状态。

支持：

- Windows COM 端口和 Unix `/dev/tty*` 端口枚举；
- 8 数据位、无校验、1 停止位、无流控（8N1）；
- 可配置波特率，范围 1–4,000,000，默认 115200；
- Python、Shell 和任意 Shell command；
- stdin、Ctrl+C Stop、超时；
- 本地工作区递归上传；
- UTF-8 文本文件，单文件不超过 1 MiB，工作区不超过 8 MiB；
- 每个串口同一进程内只能有一个运行或连接测试。

串口控制台只有一条合并输出流。`pipe` 模式依赖 SSH 的 stdout/stderr 分离，因此串口设备强制使用 `pty` 语义；前端将当前控制台行列数随运行请求传入，窗口尺寸只在启动时写入 `stty`，运行中 resize 会返回明确错误。

## Shell Execution Protocol

每次命令使用随机 nonce 生成两段 ASCII 控制标记：

```text
RS RR_<nonce>_B US
...
RS RR_<nonce>_E:<exit-code> US
```

`RS` 是 `0x1e`，`US` 是 `0x1f`。标记前的 shell prompt、命令回显和标记后的 prompt 都被解析器剥离。解析器按原始字节工作，支持标记跨串口分包，不依赖 `$`、`#` 或 `root@` prompt，也不会把用户程序输出中的相似文本当作完成标记。

包装命令通过 `sh -c` 执行目标命令，先保存并设置 termios，再发送开始标记。启动时明确设置 canonical 输入、CR→LF、回显、SIGINT 和无软件流控，退出时恢复原设置；设置失败也有带退出码 125 的完整标记。收到 Ctrl+C 后，前台子进程可以产生退出码；只有收到对应 nonce 的结束标记，已发送的任务才会被标记为完成。串口断开或停止 5 秒仍未收到结束标记时，任务失败并提示远端进程状态未知。

控制台 Ctrl+C 只在运行阶段发送一次 `0x03`，不进入 stopping、不启动 5 秒停止确认期限，也不改变原运行超时。程序捕获中断后可继续接收输入，仍以原 nonce 结束标记确认最终退出。停止按钮使用独立 `SessionControl::Stop`，保留停止状态、输入清理和 5 秒确认期限。

## 文件同步

上传将文本按最多 3 KiB 原始字节分块，每块使用 base64 和带引号的 heredoc，等待该块退出码为 0 后才发送下一块。第一块创建/截断文件，后续块追加；空文件也会创建/截断。这样不会将整文件嵌入一个超大的 `sh -c` 参数，块失败或取消后也不会继续上传或启动脚本。文件内容不会参与 Shell 展开；目录和文件名使用 Shell 单引号转义。

上传前拒绝符号链接、特殊文件、重定向路径、NUL/非 UTF-8 文件，将 CRLF 规范化为 LF，并限制最多 1024 个文件/目录。读取文件本身也有 1 MiB 上限，避免文件在元数据检查后增长导致无界读取。Unix 文件名中的反斜杠保留原义。`.git`、`.hg`、`.svn` 目录不会上传。

打开串口前检查所有生成的上传命令及最终执行命令。每个包装命令最多 16 KiB，每条物理行最多 2048 字节，不能含换行以外的 ASCII 控制字符（例如 TAB、CR、ESC、Ctrl+C）；Shell 引号无法阻止终端驱动解释这些字符。需要这类内容时应使用上传的脚本文件。开始响应的等待时间包含按波特率估算的发送时间；每块开始执行后有独立的 30 秒超时。

## 取消与连接占用

端口打开前会先做本地占用登记，运行结束或失败时释放；串口打开也会请求系统级 exclusive。完全没有发送字节时，停止可直接取消；已发送部分或全部命令时，停止丢弃剩余命令和排队输入，只发送 `0x03`，不追加换行。不再将本地写入成功视为远端取消确认；半条命令被中断后通常没有结束标记，会明确报告未确认状态。

探测及上传阶段不转发用户输入。目标进程开始前的输入暂存，停止后丢弃；收到结束标记后立即退出。读写保持公平，持续输出不会阻止 Ctrl+C 发送，控制消息和超时优先处理。

Shell V1 仍共享远端登录 Shell 的输入通道：如果进程已经退出、结束标记还在传输，已发出的输入仍可能落到 Shell；应用层不能完全消除这个窗口。raw 模式程序禁用 SIGINT 时，Ctrl+C 也可能不生效，此时报告停止未确认。需要严格进程隔离及独立停止通道时应使用 SSH 或后续 Serial Agent。

## 验证

没有可用硬件，因此使用 Tokio duplex 模拟串口，并用本机 Git Bash/Unix shell 直接执行包装命令。测试覆盖：

- 任意字节分包、错误 nonce、命令回显和 prompt 隔离；
- workspace 目录、文本转换、二进制拒绝、上传内容防 Shell 展开；
- 交互输入（包括开始标记到达前的输入排队）；
- 用户 Stop、超时、无响应、断开和登录提示符误判；
- 本机 shell 的引号、退出码、多块大文件上传与旧文件截断；使用 stty 替身验证终端初始化和恢复的调用顺序及失败标记，不等同于真实终端验证；
- 部分发送后停止、停止后延迟开始标记、连续输出时停止、块上传失败不再启动脚本、非法命令在远端操作前拒绝。

## 本次审查修复

| 问题 | 修复 |
|---|---|
| 整文件被作为单个 shell 参数，换行分段仍无法避开参数大小限制 | 按 3 KiB 分块上传并逐块确认 |
| 部分发送后 Stop 无需远端标记就报告 canceled，还会追加换行 | 只发送 Ctrl+C，必须等待确认，否则报告未知状态 |
| Stop 后晚到的开始标记仍会刷新提前排队的输入 | 停止清空队列，禁止后续刷新；上传阶段丢弃输入 |
| 开始标记早于终端设置，且 GUI 未传当前尺寸 | termios 初始化先于开始标记；前端传当前行列数 |
| 引号未防住终端控制字符，超长命令在上传后才失败 | 所有生成命令在打开端口前预检 |
| 文件大小只查元数据；Unix 反斜杠被改成路径分隔符 | 有界读取；只在 Windows 规范化路径分隔符 |

完整 Agent 协议、二进制 Artifact、远程下载和登录态管理仍属于后续阶段。硬件相关的 UART 电气参数、板卡驱动、实际 bootloader 输出和具体 shell 行为需要接入设备后再做回归。
