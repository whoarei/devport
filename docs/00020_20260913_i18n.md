# 00020 前端多语言（i18n）：中文 / English

日期：2026-09-13
状态：已实现

## 背景与目标

前端 UI 文案此前全部硬编码中文（约 30 个文件、300+ 处），需要支持中英文双语。仅做前端：Rust 后端的错误消息保持原样透传（翻译后端错误需要错误码协议，另行考虑）。

## 方案

- 库：`i18next` + `react-i18next`。资源内联打包进 bundle，`main.tsx` 顶部 `import "./i18n"` 同步初始化，无 Suspense 包装。
- `src/i18n/zh.ts` 是 key 的事实标准；`src/i18n/en.ts` 用 `typeof zh`（导出为 `Messages`）约束，漏翻或 key 拼错会编译报错。
- key 按界面域分层：`menu.*` / `titlebar.*` / `app.*` / `editor.*` / `workspace.*` / `console.*` / `run.*` / `terminal.*` / `device.*` / `about.*` / `update.*` / `dialog.*` / `unsaved.*` / `replay.*`。带变量的文案用 `{{var}}` 插值。

## 语言判定与切换（`src/i18n/language.ts`）

- 语言偏好 `LanguagePreference = "zh" | "en" | "system"`，持久化在 localStorage（`remote-runner.language.v1`），缺省或非法值视为 `system`。
- 初始语言按偏好解析：`system` 时跟随系统——`navigator.language` 以 `zh` 开头用中文，其余英文；无法检测回落中文。
- 切换入口：菜单栏「视图 → 语言」子菜单（跟随系统 / 中文 / English 三个 checkbox 项）。`setLanguage()` 解析偏好、调 `i18n.changeLanguage`、持久化并同步 `<html lang>`；MenuBar 本地持有偏好状态，保证切到「跟随系统」且解析结果不变时菜单勾选也能即时刷新。
- localStorage 访问包 try/catch（Node 测试环境无 localStorage 时静默回落）。

## 取文案的两种方式

| 场景 | 方式 |
|---|---|
| React 组件（含 aria-label / title / placeholder） | `const { t } = useTranslation()`，切换语言自动重渲染 |
| 逻辑模块（store.ts、updateStatus.ts、updateFlow.ts、workspacePicker.ts、terminalStore.ts、consoleReplay.ts、terminalIO.ts） | `import i18n from "./i18n"; i18n.t(...)`，按调用时的当前语言取值 |

`i18n/` 不反向依赖 store，无循环导入。

## 测试

断言文案的测试文件（`appUpdate` / `workspace` / `terminal` / `review`）顶部用 `test.before(() => i18n.changeLanguage("zh"))` 固定中文，避免断言随运行环境的系统语言漂移（Node ≥ 21 存在 `navigator.language`）。新断言应优先面向行为而非文案。

## 明确不做

- Rust 后端错误消息不翻译，原样透传（前端只翻译自己拼接的前缀）。
- 用户数据（设备名、文件名、工作区路径）不翻译。
- 代码注释保持中文。
- 复数规则：当前用不到，未引入。
