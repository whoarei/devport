# 00004 工作区与增量同步

基线：2026-10-20 / 0.12.0。总体关系见 [技术方案](00002-architecture.html#workspace)。本专题统一维护来源身份、文件访问、源端运行元数据与执行副本。

## 1. 来源与运行位置

`WorkspaceRef` 有两种形态：`{type:"local",dir}` 与 `{type:"device",device_id,path}`，兼容旧的本机裸路径字符串。设备来源仅支持 SSH / WSL。来源设备与运行目标分别选择，不能将当前目标当成源端状态的保存位置。

| 来源 → 目标 | 实际执行方式 | 产物位置 |
| --- | --- | --- |
| 本机 → Local | 原地执行 | 源工作区 |
| 设备 → 同一设备 ID | 原地执行 | 源设备工作区 |
| 本机 → SSH / WSL | 增量同步到固定执行副本 | 目标固定目录 |
| 设备 → 其他目标 | 先下载到本机临时目录，再按目标管线运行 | SSH/WSL 固定目录；Local 为临时副本 |
| 任意有效来源 → Serial | 经本机来源或暂存后，全量文本上传到每次运行目录 | 串口目标运行目录 |

跨设备暂存目录为系统临时目录下 `remote-runner-stage-<run_id>`，成功、失败、取消均由守卫清理。Local 暂存副本中的产物随之删除。远端产物不自动回传；持久执行目录不自动清理，也不保留历史源码快照。

## 2. 编辑安全

本机工作区校验 canonical 根及路径祖先，拒绝符号链接、junction / reparse 重定向和特殊文件。设备路径必须为绝对 POSIX 路径，无 `.` / `..`；设备配置中的 `~/` 则在实际连接后解析目标用户 HOME，不能猜 `/home/<user>`。

SSH 根 canonicalize 后，根以下逐组件 `symlink_metadata` 拒绝链接；WSL helper 通过 dirfd 与 `O_NOFOLLOW` 逐级打开。每个相对路径仍须在 Rust 边界验证，不能依赖树组件提供的名称。SFTP 的多步属性检查无法提供对恶意并发路径替换的完整事务隔离。

编辑器仅支持不超过 1 MiB 的 UTF-8 文本，保留 `revision`（内容 SHA-256）、换行类型与 BOM。写入携带 `expectedRevision`，冲突不覆盖原文件。本机和 WSL 使用临时文件替换；SSH 编辑保存与通用传输是不同实现，不应把传输层的无删除回退保证自动套到所有编辑接口。

编辑会话 `remote_workspace::SessionStore` 为单槽长连接，连接错误后失效；切换或关闭工作区释放。运行、文件传输和运行元数据写入不借用该会话。

编辑器修改经 `FILE_OPERATIONS` 守卫，与准备、同步、停止阶段互斥；运行阶段仍不能阻止外部进程改文件。目录树按需展开，重命名联动标签和历史来源；删除或切换有脏文件时走保存/丢弃/取消。

本机工作区空白区和目录条目的右键菜单提供“在系统文件管理器中打开”：分别打开工作区根目录和所选子目录。Rust 复用目录路径校验，拒绝越界、链接、重定向及非目录目标，并将 Windows canonical 路径还原为可供系统程序使用的形式。设备工作区不显示此入口，不将 SSH/WSL 路径当成本机路径打开；打开失败在工作区错误条提示。

## 3. `.runner`：源工作区拥有的状态

```text
<源工作区>/.runner/
├── config.json       # schema 1，run_defaults.cwd
├── commands.json     # schema 1，入口/参数和来源索引
└── write.lock        # 写入期间排他锁
```

`config.json` 上限 256 KiB，只保存共享 cwd 默认值，不保存 Python 版本、依赖或源码搜索目录。目标、按设备的 Python/Bash 选择、附加 env、模式、超时是客户端偏好，见 00007。

命令历史 ID 是以下 JSON 数组 UTF-8 字节的完整 SHA-256：

```text
["runner-command-v1", entry_kind, entry_value, args_array]
```

设备、环境、cwd、时间和来源索引均不进入 ID。相同入口参数合并为一条；参数边界及顺序参与身份。读取时重算错误/旧 UUID ID，合并来源及最近时间；单条全局删除会从所有关联菜单移除。编辑入口或重命名重算并合并 ID；模块无法唯一推导时保留名称并标记 `needs_edit`，执行前要求处理。

历史最多 200 条且实际 UTF-8 pretty JSON 不超过 1 MiB，追加时淘汰整条最旧记录，保留当前命令；外部已有超限、损坏、未知 schema 文件保留并报错。元数据使用安全 Host、排他锁、revision 再检查、同目录临时文件和原子发布；不采用删除原文件再写入的回退。遗留写锁通过 `runner_lock_info` / `recover_runner_lock`，按用户核对后的所有者 revision 恢复。

历史写入发生在进程成功启动后；失败不使已经开始的运行失败，而是提供警告与重试。准备/重建不记为脚本历史。根 `.runner` 在运行扫描、暂存、上传的限额统计前排除；用户主动文件传输仍可复制它，不执行状态合并。

## 4. 运行上传策略

| 路径 | 单文件 | 总内容 | 条目 | 相对路径 | 文件处理 |
| --- | --- | --- | --- | --- | --- |
| SSH 上传 | 64 MiB | 256 MiB | 4096 | 1024 字节 | 二进制可用，跳过链接 |
| WSL 上传 | 16 MiB | 64 MiB | 4096 | 1024 字节 | 二进制可用，拒绝链接 |
| Serial 上传 | 1 MiB | 8 MiB | 1024 | 512 字节 | UTF-8、无 NUL，拒绝链接 |
| 跨设备暂存 | 64 MiB | 256 MiB | 4096 | 依源端安全路径校验 | 跳过链接及 `.git`，再受目标限额约束 |

上传过滤版本库目录和根 `.runner`；普通脚本文本按上传策略将 CRLF 转 LF。根 `pyproject.toml`、`uv.lock`、`.python-version` 在 SSH / WSL 路径保持原始字节，以保证计划输入哈希一致；Serial 仍按文本 LF 语义核验。Local 原地执行不进行上传转换。

这些限额独立于编辑器 1 MiB 和文件传输 2 GiB，不能互相替代。扫描与读文件均有界，条目类型和限额不能只在前端检查。

## 5. SSH / WSL 固定目录和来源身份

```text
<workspace_root>/<来源工作区目录名>/
├── workspace/          # 源码与生成产物，实际执行根
└── .sync/
    ├── identity.json   # 不覆盖发布的来源认领
    ├── manifest.json   # 上次成功清单及来源属性缓存
    ├── pending.json    # 未完成同步恢复记录
    └── lease.json      # 从同步直到确认进程退出的目录锁
```

来源键为 `SHA256(JSON(协议版本, workspace-client-id, canonical 原始 WorkspaceRef))`。客户端 UUID 保存在应用配置目录 `workspace-client-id`。跨设备必须在改写为临时来源之前计算身份和目录名。文件内容、分支、入口、参数和运行 ID 不影响身份。

目录名原样保留中文和空格，但必须是安全单路径组件，非法名称直接拒绝。不同来源同名、换客户端身份、移动来源目录后遇到已有身份，均报冲突；已有非空目录无身份也不接管。不追加哈希后缀，不迁移或删除旧 UUID / `rr-<key>` 目录。可识别的来源与目标递归重叠（包括 Local↔WSL 映射）拒绝。

## 6. 差异计算与缓存边界

清单存相对路径、类型、上传字节 SHA-256、大小、权限及可选 `source`。`source` 包含缓存版本、来源原始大小、纳秒 mtime 字符串和辅助身份；Windows 使用创建时间，Unix 使用设备号/inode/ctime。上传后大小与来源大小不同，特别是 CRLF 转换后。

来源大小、mtime 与缓存规则相同则复用上传摘要；权限也未变、无 `pending` 时，直接信任成功清单并跳过目标路径属性和内容读取。辅助身份用于本次同步期间变动检查，不参与跨次缓存命中。仍执行目录遍历、链接/路径校验和原始大小/条目限额。

这是一项明确的性能取舍：同长度改写且保留 mtime 可能命中旧摘要；目标单独修改、删除或 chmod，在来源属性不变时不会被发现。需要再次检查该路径时修改来源内容或修改时间。不能表述为每次校验整棵目标目录或自动修复所有目标偏差。

新增、变更、删除候选、旧清单无缓存或存在恢复记录时，必须核验实际目标。来源重读及远端预检后/提交前属性复核发现变动则失败，不启动程序。

SSH 优先使用最多 16 路径一批的 POSIX `stat -c` / `sha256sum` 预检，命令 ≤24 KiB、响应 ≤64 KiB，建立通道 10 秒、执行 30 秒超时；回复校验 nonce、索引、数量、摘要。每批抽查 SFTP 属性表示，缺失项也由 SFTP 再确认；不兼容、异常、超时整批丢弃并回退 SFTP，不能增加 Python/rsync 必需依赖。WSL `tf_inspect` 同样每批最多 16 条，用 dirfd + no-follow 核验并返回摘要。

| 差异 | 处理 |
| --- | --- |
| 内容相同 | 不上传内容；必要时更新权限/来源缓存 |
| 新来源文件、目标缺失 | 安全上传 |
| 已受管且需要检查的文件改变/丢失 | 从来源恢复 |
| 未受管同名文件内容不同 | 全部预检失败，保留目标 |
| 未受管同名文件内容相同 | 可接纳为受管源码 |
| 来源删除受管文件 | 仅在目标仍为已知版本时删除 |
| 待删除文件被目标改写 | 冲突并保留 |
| 文件/目录类型变化 | 冲突，不递归强制替换 |
| 来源删除目录 | 只删除空的受管目录；未知产物保留 |

## 7. 提交、恢复和锁

顺序：可取消等待进程内目录队列 → 不覆盖竞争远端 `lease` → 读取成功清单 → 扫描与完整候选预检 → 发布 `pending` → 逐文件操作 → 发布新 manifest → 删除 pending → 环境准备/执行 → 确认结束 → 释放锁。

文件写同目录 `.rr-transfer-<uuid>.part`，完整关闭后安全发布；修改/删除前重新比较目标属性与摘要。SSH 缺少可靠硬链接/原子替换能力则报错，不先删除旧文件。提供单文件提交安全，不提供整树回滚。中断后不启动脚本，下一次按真实内容恢复。

`pending` 包含旧清单、新清单、未消除的所有权和精确临时文件路径；重复中断仍保留已发布文件归属。只清理记录中的工作区临时文件，不通配删除同前缀用户文件；应用独占 `.sync` 可清理符合本应用格式的残留元数据临时文件。manifest 上限 8 MiB、恢复记录 32 MiB，恢复条目/字节预算最多正常来源两倍。

目录队列覆盖同一目标账户、配置根和目录名，远端锁防止别名配置覆盖。不同目录可并行；等待取消不影响持锁任务。锁持有至确认退出。SSH 断线、未确认终止或解锁失败保留锁并报路径，不按年龄接管。先确认旧进程已停止，再检查并人工删除错误信息指向的 `.sync/lease.json`。此锁与 `.runner/write.lock`、环境锁是三种不同资源。

清单损坏不得触发猜测性删除；清单丢失可接纳相同内容，但无法识别已从来源移除的旧源码，不删除未知内容。新清单可读旧的无 `source` 格式；旧应用可能拒绝新增字段，回退版本前应评估此兼容边界。
