# SSH / WSL 工作区目录复用与增量同步

日期：2026-10-19

状态：已实现。

## 1. 范围

本地工作区上传至 SSH / WSL 目标，或设备工作区跨设备运行时，不再按运行 UUID 创建执行目录。相同来源工作区在相同目标根目录中复用固定目录，仅上传有变化的文件。

串口仍按 `<workspace_root>/<run_id>` 全量上传 UTF-8 文本；Local Shell 及设备工作区在同设备运行继续原地执行。独立文件传输面板、运行时管理命令使用的一次性准备目录不改用持久执行目录。不扫描、迁移或删除旧 UUID 目录和旧 `rr-<工作区键>` 目录。

## 2. 身份与目录

应用配置目录新增 `workspace-client-id`（持久化 UUID）。工作区键为 SHA-256：

```text
JSON(协议版本, workspace-client-id, 规范化后的原始 WorkspaceRef)
```

本机来源使用 canonical 路径；设备来源使用来源设备 ID 和 canonical 路径。跨设备运行必须在暂存下载、改写请求之前计算身份和目录名，不能使用 `remote-runner-stage-<run_id>`。文件内容、入口、参数、Git 分支和运行 ID 不参与身份。

2026-10-19 调整：远端目录直接采用原始来源工作区的目录名，工作区键仅保存在隐藏元数据中。例如来源目录名为 `work`、目标根为 `/home/xx`，执行位置固定为 `/home/xx/work/workspace`。名字保留中文和空格，不增加哈希后缀；在 Rust 边界验证为单个安全路径组件，拒绝根目录、非法名字和路径穿越，不通过替换字符将不同名字合并。

目标布局：

```text
<workspace_root>/<工作区目录名>/
├── workspace/                  # 实际 cwd 根，源码与产物
└── .sync/
    ├── identity.json           # 不覆盖发布的来源身份，用于同名冲突保护
    ├── manifest.json           # 最近成功的来源快照
    ├── pending.json            # 未完成事务的恢复记录（成功后删除）
    └── lease.json              # 同步与运行共同持有的远端锁
```

`run_id` 仍独立生成，用于事件、控制、输出日志和历史。共享目录随后续同步更新，历史记录不能作为旧源码快照使用。

首次使用名字时，通过不覆盖发布 `identity.json` 认领目录；同一来源后续复用。不同路径的同名工作区、不同客户端身份使用同名目录，均明确报来源冲突，要求更改来源目录名或目标根目录，不静默共用或追加哈希。已有非空目录缺少身份信息时也拒绝认领，保护用户数据。移动来源到其他父目录或换用配置目录会改变身份；即使目录名相同也不会自动接管旧目录。旧哈希目录保留，首次使用新命名布局会重新同步一份工作区。

目标根由安全文件服务逐级创建，SSH 拒绝创建路径中的链接，WSL 使用 dirfd / `O_NOFOLLOW`。可识别的 Local↔WSL 映射以及同账户的设备路径重叠会被拒绝，避免把目标目录递归收进来源。

## 3. 扫描、摘要与差异

`workspace_sync.rs` 复用 `workspace_upload` 的扫描、过滤、模式和换行转换；摘要基于实际上传字节。扫描和本机读文件在 blocking 线程中进行，每次最多保留一个有界文件内容。上传前重读并核验其摘要，来源在同步期间改变则本次失败，不执行脚本。

2026-10-20：本地源文件的摘要缓存保存在目标已有的 `.sync/manifest.json` 中，不在 Windows 应用目录或源工作区 `.runner` 中写入缓存。同步先读取并验证上次成功提交的清单，再扫描本地文件属性；条目新增可选 `source`，包含缓存规则版本、原始字节数 `size`、修改时间纳秒字符串 `modified_ns` 和辅助身份 `identity`（Windows 创建时间；Unix 设备号、inode 与 ctime）。原始大小、修改时间相同且缓存规则版本匹配时，复用清单中的上传摘要和上传后大小，跳过本地内容读取；辅助身份只用于同步期间的变动检查，不影响跨次缓存命中。新文件、大小/时间变化、旧清单缺少缓存、缓存规则版本变化时重新读取并计算；无法取得修改时间时不缓存。目录遍历、本地路径/链接检查、原始大小与条目限额始终执行。

`source.size` 与现有条目 `size` 含义不同：前者是 Windows 等来源的原始文件大小，后者是实际上传字节数，脚本 CRLF 转 LF 后可能变小。源文件时间变化但规范化内容相同时，不上传内容，仍提交最新源属性，使下次扫描命中缓存。缓存与清单一起原子提交，未完成事务的 `pending.next` 不作为缓存基准；恢复时继续使用已提交清单和现有所有权保护。清单及恢复记录缺少 `source` 的旧格式可由新版本读取，工作区身份版本和目录不变；旧版本应用因拒绝未知字段，不能直接读取新增字段后的清单。

远端预检后，以及文件操作完成、提交清单前，再检查源文件路径、类型与完整属性；即使文件命中摘要缓存，检测到中途改动也会失败。该优化采用属性快判：同长度内容被改写且修改时间被保留时，可能复用旧摘要。同步管线的优化不省略跨设备来源下载到临时目录的步骤。应用日志新增 `workspace source scan`，记录 `cached_files`、`hashed_files` 和本地扫描耗时 `elapsed_ms`，便于判断收益。

限额保持不变：SSH 单文件 64 MiB、总计 256 MiB；WSL 单文件 16 MiB、总计 64 MiB；均最多 4096 条目、相对路径 1024 字节。跳过版本库元数据和根 `.runner`，继续按传输策略处理符号链接和重定向。复用文件传输层安全路径规则，拒绝该层不支持的路径组件。

清单记录版本、工作区键，以及相对路径、文件/目录类型、SHA-256、大小和权限。所有远端清单都限制读取大小并验证身份、条目数、总大小、每条路径及父目录记录；清单损坏不会触发猜测性删除。

2026-10-20 调整：信任已成功提交的 manifest。没有 `pending.json` 时，来源文件的原始大小、修改时间与缓存规则匹配，且权限未变化，就直接跳过远端属性、摘要和内容读取；已受管且类型/权限未变的目录也跳过远端预检。这里比较的是清单中的来源属性与本地属性，不比较两台机器的时间。文件被目标端单独修改、删除或改变权限时，不会自动发现或修复；本地属性变化后，该路径才重新检查。首次同步、旧清单缺少来源缓存、新增/变更/待删除路径，以及有恢复日志的同步，继续核验实际远端内容：

- 2026-10-20 远端批量预检：把本次来源和旧受管条目的路径合并去重，排除 manifest 已确认未变的路径，其余每批最多 16 条，集中取回文件类型、大小、修改时间、权限和 SHA-256。完成所有批次后才生成并执行文件修改。全量未变时执行零次工作区路径批量检查；目录、缺失文件、待删除的旧受管文件在需要预检时使用同一份结果。
- SSH 优先使用一个有界 POSIX shell 命令完成一批属性/摘要检查，`stat -c` 和 `sha256sum` 可用时启用。所有路径均在 Rust 验证后逐参数引用；目标端逐层拒绝链接和非目录祖先，读前/读后检查属性（含设备号、inode、纳秒时间字符串），只返回带随机批次标记和顺序索引的有界结果。属性按现有 SFTP v3 的秒精度和 UID/GID 表示转换，供后续写入时比较。命令上限 24 KiB，回复上限 64 KiB，通道建立超时 10 秒、批次执行超时 30 秒；取消关闭该批次通道，保留共享连接用于释放目录锁。命令不支持、回复异常/不完整或超时时丢弃整批结果并禁用本会话的批量加速，回退到原有 SFTP + 可选单文件 `sha256sum`，不增加 SSH 目标 Python / rsync 的必需依赖。过长的批次命令直接走回退。回退也移除了同步层重复的一次 `stat`。
- WSL 新增 `tf_inspect`，在现有 helper 会话里每批处理至多 16 条路径，使用 dirfd + `O_NOFOLLOW` 打开文件，核验打开前、读取后和路径当前属性及 ctime，返回属性和摘要而不传回文件内容。Rust 和 helper 两端均验证路径、批次数和文件大小限额。保留 `tf_hash` 兼容既有文件服务。
- 回退 SFTP 时，需要预检的文件仍可能被完整读回；全量未变时只保留目录身份、锁、清单等元数据流量。“零上传”指工作区文件内容。

批量结果只用于本次只读预检，不缓存为写操作的检查结果。上传、chmod、删除仍在操作前重新获取摘要/属性并与预检值比较，保留来源重读校验、原子发布及未知产物保护。SSH 同步租约持有的已认证连接还供运行会话、目标配置核验、运行时输入复核和解释器探测复用，各自使用独立 channel；同设备来源的初始检查连接也可复用，不借用编辑会话。新增 `workspace remote preflight` 和 `workspace launch checks` 耗时日志，前者记录实际检查数 `paths`、清单跳过数 `manifest_skipped`（含目录）；debug 级 `workspace inspection` 记录批量命中数及回退路径数。

为兼容缺少 UID/GID、权限等字段的 SFTP 服务，每个实际执行的批次通过 SFTP 抽查一个已有路径的属性表示，发现与命令输出不同则禁用加速并回退。所有 shell 报告不存在的路径也通过 SFTP 确认，避免 `test -e` 的访问限制或命名空间差异被误判为待创建文件；缺失条目仍执行完整 SFTP 路径检查。

| 情形 | 行为 |
| --- | --- |
| 来源大小、修改时间和权限与成功清单一致 | 直接跳过远端检查，信任该清单 |
| 文件不存在 | 上传新文件 |
| 文件内容相同 | 跳过内容上传 |
| 只有权限不同 | 修改权限，上传字节为零 |
| 需要预检的已受管文件内容改变/缺失 | 根据来源恢复 |
| 未受管同名文件内容不同 | 冲突，整个预检失败 |
| 未受管同名文件内容相同 | 安全接纳为来源受管文件 |
| 来源删除受管文件 | 验证远端仍是已知版本后删除 |
| 待删除文件被远端改写 | 冲突，保留该文件 |
| 文件与目录类型变化 | 冲突，不隐式递归替换 |
| 重命名 | 删除旧文件、上传新文件 |
| 来源删除目录 | 只移除已空的受管目录；非空目录及未知产物保留 |

所有需要预检的路径检查完成后才开始修改工作区文件。运行产生且未登记为来源的日志、结果、缓存不参与删除。工作负载主动覆盖受管源码文件后，来源大小/修改时间不变时会保留远端改动；需要再次同步该路径时，可修改本地文件或其修改时间。

## 4. 提交与恢复

状态顺序：

```text
获取目录锁 → 读取清单/扫描 → 排除未变路径/其余预检 → 发布 pending → 执行文件操作
→ 发布 manifest → 删除 pending → 准备运行环境/执行 → 确认结束 → 释放目录锁
```

`pending` 保存成功清单、预期新清单、尚未消除的受管条目及精确的上传临时文件路径。反复中断恢复时继续保留已发布文件的所有权，避免新增文件因未进入正式清单而变成孤儿。

每个文件写入同目录 `.rr-transfer-<uuid>.part`，完整关闭后安全发布/原子替换。写入按块检查取消标志，失败不发布半个文件。修改/删除前重新检查目标摘要与属性。SSH 需要 `hardlink@openssh.com` 和 `posix-rename@openssh.com`；缺少能力时明确报错，不先删除旧目标。

下次同步先清理恢复记录中列出的精确工作区临时文件；不会通配清理运行目录中的同名前缀文件。应用独占的 `.sync` 中可以清理符合应用临时文件格式的残留元数据写入文件。然后按实际内容重算差异，完成恢复。中断时不启动脚本；保证单文件提交安全，不提供整树事务回滚。

清单上限 8 MiB，恢复记录上限 32 MiB；恢复期间保留的条目/字节预算最多为正常来源的两倍，超过预算需人工检查，不无限扩大。清单丢失时可重新接纳内容相同的文件，但无法识别已经从来源删除的旧文件，因此不自动删除未知内容。

## 5. 目录锁与生命周期

- 进程内按目录名、目标账户和配置根目录排队，等待可取消；运行状态通过 `waiting_workspace` 显示等待。
- 远端 `lease.json` 用不覆盖的安全发布竞争，记录随机所有者、运行 ID 和创建时间。同一路径的其他账户别名配置即使没有进入同一本机队列，也不能覆盖锁。
- 持锁覆盖同步、环境准备和整个执行周期。无工作区的命令、原地运行和串口不接入该锁。
- 同目录后续运行串行；不同目录可并行。暂停或取消等待不打断当前持锁任务。
- 同步/准备失败、取消发生在执行前时，尽力释放锁；SSH 收到退出消息或 WSL 明确报告执行结束后释放。
- SSH 断线或强制本地关闭但未确认远端退出时保留锁；清理锁失败也会输出警告。不能仅凭锁年龄自动接管。需要确认旧进程已停止，再检查/删除错误信息所指的 `.sync/lease.json` 后重试。当前不增加自动找回旧进程或锁恢复 UI。

## 6. 接口与展示

`RunStatus.workspace_sync` 可选，记录 `destination`、`added`、`updated`、`deleted`、`skipped`、`permissions` 和 `uploaded_bytes`，随现有状态事件和历史持久化，不混入工作负载原始输出。控制台显示路径及统计，工具栏显示可取消的等待状态；zh/en 均提供翻译。旧历史缺少这些字段仍可读取。2026-10-20：进入工作区同步时清除此前的运行时阶段，避免继续显示“同步中 · 校验项目”；后续运行时准备再发布自己的阶段。

文件操作复用 `file_transfer::host::Host`，新增根目录创建、受管文件 unlink、空目录 rmdir、chmod 与远端摘要；不借用单槽编辑连接。WSL 扩展独立 `tf_*` 会话，运行 helper 继续以 `in_place=true` 打开同步完成的目录、零文件上传；helper 源码仍经 stdin 传入。
