# 本机与 SSH / WSL 设备文件传输规划

日期：2026-10-12

状态：第一阶段主体已实现（2026-10-13）；后续增强及验证结果见第 12 节。

## 1. 目标与范围

用户已明确：文件共享指本机与 SSH / WSL 设备之间上传、下载文件。产品入口建议命名为「文件传输」，让操作方向与结果更明确。

典型场景：

- 把本机脚本、配置、数据集或固件传到设备的指定目录。
- 从设备下载日志、截图、模型、运行结果等文件。
- 在 Windows 和 WSL 发行版之间复制项目目录或二进制文件。
- 从现有工作区右键发起传输，不必先运行脚本。

第一阶段支持本机 ↔ 单台 SSH / WSL 设备，支持普通文件、多选文件和递归目录。传输完成后两端是独立副本，后续修改不会自动同步。

暂不包含目录挂载、SMB / NFS、局域网共享链接、自动双向同步、远端之间直接传输、串口通用文件传输、暂停续传及后台独立服务。串口继续保留现有 UTF-8 工作区上传能力，不扩展为任意二进制传输。

## 2. 已有能力与缺口

依据 `00029_20260917_remote-workspace.md` 及当前代码：

| 已有能力 | 可以复用的部分 | 需要新增的部分 |
| --- | --- | --- |
| SSH 工作区 SFTP 访问 | SSH 配置、认证、known_hosts、连接和路径校验思路 | 面向传输的流式读写、文件属性、进度、取消与提交能力探测 |
| WSL helper 的 `fs_*` 文件服务 | stdin 引导、结构化消息、dirfd / `O_NOFOLLOW`、分块方式 | 独立传输消息、传输限额、流式收发、取消和完整结果确认 |
| 本机工作区文件服务 | 根路径检查、相对路径校验、Windows 重定向检查 | 任意选定目录、二进制流式 IO、目标文件安全提交 |
| 跨设备运行暂存 | 遍历与清理思路 | 用户指定落盘位置、多文件任务、显式传输规则 |
| 面板注册表和 i18n | 布局、显示开关、中英文资源 | 文件传输面板与独立状态管理 |

不能直接把编辑器接口包装成传输接口：

- 编辑器读写上限约 1 MiB，要求文本解码；通用传输必须原样保留二进制字节和换行。
- `RemoteWorkspace::read_raw` 返回完整 `Vec<u8>`，大文件需要改用有背压的流式接口。
- 工作区列表过滤部分隐藏项，传输浏览需要独立的「显示隐藏文件」选项。
- WSL 编辑保存依赖小文件 revision，不能直接套用于大文件、新文件和目录复制。
- SSH 编辑保存遇到标准 rename 不能覆盖时会先删旧文件。传输写入不能沿用此回退。
- 编辑会话是 `SessionStore` 单槽长连接。传输必须拥有独立会话，避免阻塞编辑和运行。
- 当前运行状态没有明确持久化实际产物目录；历史下载入口需要另外设计执行位置元数据。

本功能采用独立 `TransferPolicy`，不修改现有运行上传、串口、编辑器和跨设备暂存的限制。

## 3. 交互方案

### 3.1 入口与布局

- 文件菜单：「文件传输…」，打开中心区的文件传输面板。
- 工作区右键：本机文件「上传到设备…」，设备文件「下载到本机…」；把选择与路径带入面板。
- 设备配置列表提供「浏览文件」入口，预选对应设备。
- 面板按现有注册表接入；默认隐藏，用户打开后与编辑器、控制台采用同一布局体系。

面板包含三个区域：

| 区域 | 内容 |
| --- | --- |
| 左侧：本机 | 目录选择、路径、上级目录、刷新、显示隐藏文件、多选列表 |
| 右侧：设备 | SSH / WSL 设备选择、当前目录、路径、上级目录、刷新、多选列表 |
| 底部：传输队列 | 方向、源与目标、状态、文件数、字节数、速度、取消、错误详情、重试 |

目录浏览采用逐层加载。列表显示名称、类型、大小、修改时间；符号链接显示为不可传输并说明原因。浏览权限沿用本机进程或设备用户权限。

按钮明确写「上传 →」和「← 下载」。第一阶段以按钮和右键为主，后续再增加拖放。

### 3.2 一次传输

1. 选择设备和两侧目录。
2. 在源侧选择文件或目录，点击上传 / 下载。
3. 后端预检，展示目标、预计文件数与大小、同名项、不支持项。
4. 用户选择同名策略后开始传输。没有冲突时可直接入队。
5. 队列展示扫描、等待、传输、提交及终态；完成后刷新目标列表。

入队后任务固定源目录、目标目录、设备及配置版本。之后切换工作区、目录或设备，不改变已有任务。未开始任务若设备配置已变，应标记需要重新检查，不能静默使用新配置。

关闭面板继续传输；应用最小化到托盘继续传输。真正退出应用且有活动传输时，提示取消传输后退出或继续等待；退出时不给出自动完成的承诺。

### 3.3 文件与目录语义

- 选中文件 `a.bin`，目标目录为 `/data`，结果为 `/data/a.bin`。
- 选中目录 `project`，结果为 `/data/project/...`，保留空目录。
- 多选项保持各自名称；不隐式创建额外包裹目录。
- 同名目录只做逐文件合并，不删除目标中额外存在的文件。
- 文件与目录同名属于类型冲突，第一阶段拒绝该条目，不能自动删除或替换。
- 本机与 WSL 挂载路径可能指向同一对象；需检测可识别的别名及「目标位于源目录内」的情形。无法可靠排除递归复制时应拒绝该操作。

第一阶段提供「跳过」「保留两份」「覆盖」三种同名文件策略，默认保留两份，例如 `report (1).csv`。同一批任务可统一应用策略。

「保留两份」必须使用不覆盖目标的提交能力；不能只凭一次存在性检查生成名字。覆盖必须用户明确选择，并在提交前复查目标是否变化；检测到变化时重新报冲突。

## 4. 后端设计

### 4.1 模块与对象

建议新增 `src-tauri/src/file_transfer/`：

- `manager`：任务、队列、并发、取消、快照和事件。
- `plan`：枚举、预检、映射、同名冲突和批量策略。
- `local` / `ssh` / `wsl`：文件属性、列表、分块读写、提交、清理。
- `policy`：路径、类型、大小、条目和超时规则。

前端建议采用 `FileTransferPanel`、独立 transfer store、API 类型及 `zh.ts` / `en.ts` 资源。传输状态不混入 `RunManager` 或编辑器 store。

核心数据：

| 对象 | 内容 |
| --- | --- |
| TransferEndpoint | Local：选定的规范目录；Device：设备 ID、目录、连接配置版本 |
| TransferPlan | 后端生成的计划 ID、相对条目、目标映射、总量、冲突、不支持项、有效期限 |
| TransferTask | ID、方向、计划、策略、状态、统计、失败条目、时间 |
| TransferItem | 相对路径、类型、大小、源属性快照、目标属性快照、最终名称、结果 |

前端传入意图；后端重新解析路径、查询文件类型和应用限额。前端不能通过修改计划或目标映射绕过检查。计划预检不锁定外部文件系统，执行与提交仍需复查。

浏览与任务端点均选定一个根目录，后续操作仅接收经过后端校验的相对路径。切换浏览根需要新建端点，不能通过 `..` 逃出当前根。新建目标根第一阶段可通过浏览器创建目录后再选定。

### 4.2 传输协议

- SSH：使用 SFTP，复用认证与主机身份校验；独立连接，不要求远端安装 Python。
- WSL：复用 helper 启动方式，用新增传输消息族隔离编辑限额和状态；路径与数据仍通过结构化协议传递。
- 文件内容只在 Rust / helper / SFTP 之间流动，前端仅接收元数据和进度。
- 读写均使用有界缓冲和背压，不整文件加载，也不构建整个目录内容快照。
- WSL 初版沿用 48 KiB 原始数据块的 base64 控制帧，保留现有单帧约束；之后依据测量决定是否升级独立二进制通道。
- WSL helper 源码继续经 stdin 下发，保留命令行长度回归测试。

候选命令：`transfer_list_dir`、`transfer_plan`、`transfer_start`、`transfer_cancel`、`transfer_snapshot`、`transfer_retry_failed`。具体签名在实现前确定。

### 4.3 队列与状态

主流程：`scanning → queued → transferring → committing → completed`。

其他状态：`awaiting_conflict`、`canceling`、`canceled`、`failed`、`partial`；连接中断后无法确认提交结果的条目标记 `unknown`，需重新检查。

- 扫描时总量未知，不显示虚假百分比；确定计划后显示文件数和总字节。
- 默认最多同时执行 2 个任务，同一设备最多 1 个传输任务；单任务逐文件执行。
- 浏览使用独立轻量会话和超时，传输不会占用编辑会话。独立连接不保证带宽互不影响。
- 进度事件建议每 100–200 ms 合并一次。终态可靠送达，并通过带序号的后端快照恢复漏失事件。
- 一个条目发生普通权限或文件变化错误可继续其他条目；连接失效则停止该任务剩余项。
- 部分成功必须列出成功、失败、跳过、尚未开始项。重试仅针对失败或未开始项，先重新预检；未知项先核对，不能盲目覆盖。

## 5. 写入安全与异常语义

### 5.1 写入与提交

目标父目录中独占创建 `.rr-transfer-<任务ID>-<随机值>.part`，以受限权限写入。完整写入、关闭并核对字节数后，才发布到最终名称。

- 本机 / WSL：使用平台可用的原子替换及不覆盖提交操作；实现前分别确认 Windows、POSIX 的语义。
- SSH：探测服务端扩展。覆盖优先采用 `posix-rename@openssh.com`；没有可靠替换能力时，拒绝覆盖，保留「跳过 / 保留两份」选项。不采用删除原文件再改名。
- 没有可靠的不覆盖提交能力时，也不能承诺安全保留两份，应报告能力不足。
- 提交成功后再报完成；单纯 EOF、发送完最后一块或事件中断都不能代表成功。
- 目录传输按文件提交，不提供整棵目录事务。取消或失败后，已提交文件与已创建目录保留并列入结果。

OpenSSH 确实定义了覆盖 rename 和 fsync 扩展，但扩展支持需协商，不能假设每个 SFTP 服务端都具备。参见 [OpenSSH 协议说明](https://github.com/openssh/openssh-portable/blob/master/PROTOCOL) 与 [规范目录](https://www.openssh.org/specs.html)。项目当前依赖为 `russh-sftp = 2.4`，实现前检查该版本的接口，不能根据最新版文档推断 API。

预检、属性复查与原子 rename 不等于跨进程条件写入：标准 SFTP 的 LSTAT / OPEN / RENAME 无法完全排除其他进程在检查与提交之间修改路径或目标。第一阶段定位于用户有权访问的正常目录；对权限可被不可信进程操纵的目录，不承诺严格抗竞态隔离。实现评审必须明确剩余窗口；不能宣称「逐级 LSTAT 即完全防逃逸」。

### 5.2 取消、断线与退出

- 每个数据块与提交前检查取消。进入不可中断的提交后，以实际提交结果为准；已提交条目报成功，停止剩余项。
- 取消仅停止本次文件操作。WSL 只结束对应 helper，会话结束不终止整个发行版。
- 尽力删除当前任务未提交的临时文件；断线时可能残留，应记录所属设备、根、任务与准确临时名称，下次重连核对后清理。
- 不按通配符批量删除 `.part`，不删除其他任务或用户文件；残留清理失败可见。
- 应用异常退出后，历史活动任务标记「已中断」，不自动继续。若提交确认丢失，核对目标后再决定清理或重试。
- 无法确认原文件是否已替换时明确报告未知，不把它归为确定失败或自动重新覆盖。

### 5.3 源文件变化与完整性

预检记录源大小与修改时间，实际读取使用打开句柄的属性，读取结束再次检查属性和长度。发现变化时不发布临时文件，提示源文件已变化。

这些检查只能尽力发现变化，不能提供原子快照。正在持续写入的日志建议先停止写入或另存快照后下载；普通目录传输也不保证所有文件来自同一时刻。

第一阶段保证协议传输与长度核对，结果中明确校验级别；可选完整 SHA-256 校验列为后续增强，SSH 端可采用 SFTP 复读计算，不能依赖远端一定安装哈希命令。长度相同不应表述为内容已通过哈希验证。

## 6. 路径、过滤、权限和限额

### 6.1 路径与文件类型

- Rust 边界校验每一级相对路径，拒绝绝对路径、`..`、NUL、非法分隔符及平台特殊路径。
- 本机检查 symlink、junction / reparse 重定向；WSL 延续 dirfd + `O_NOFOLLOW`；SSH 延续根规范化与逐级 LSTAT，并承认上一节所述协议竞态边界。
- 普通文件和目录可传；符号链接、设备节点、FIFO、socket 跳过并展示理由。硬链接按普通文件复制内容，不保留链接关系。
- 跨平台名称不能静默改名：Linux 到 Windows 的保留名、尾随点空格、非法字符、大小写碰撞等在预检中逐项报错。
- 检查规范目标是否位于源目录内；边遍历边写入不能形成递归复制。
- 内容不做 UTF-8 检查或换行转换。

### 6.2 隐藏文件与过滤

显示隐藏文件仅影响列表；递归复制目录默认包含隐藏项。单独的排除规则控制传输范围，预检必须展示实际规则和被排除数量。

通用传输默认不沿用运行上传的 `.git` 等过滤；用户可选择「项目文件」预设排除 `.git`、`.venv`、`node_modules` 等。配置与隐藏文件可能正是需要复制的内容，不能无提示丢失。

### 6.3 权限与属性

- 默认使用目标端当前用户身份与新建文件权限，不复制 owner、ACL、xattr，也不复制 setuid / setgid 等特殊位。
- 覆盖已有文件时尽量保持其基本权限；无法满足时提前说明或拒绝，不静默改变权限。
- 提供「保留可执行位」选项，仅在源和目标都能提供可靠 POSIX 模式时适用。
- Windows 来源脚本默认不猜测可执行位，用户可在设备终端设置或通过解释器运行。
- 修改时间保留作为可选项；失败列为属性警告，区分内容成功与属性失败。

### 6.4 初始传输策略建议

下列是待性能验证的产品默认值，不代表现有代码已支持：

| 项目 | 建议初始值 |
| --- | --- |
| 单文件 | 2 GiB |
| 单批累计文件内容 | 10 GiB |
| 单批条目 | 10,000，含目录 |
| 目录深度 | 64 层 |
| 活动任务 | 全局 2；单设备 1 |
| 未开始任务队列 | 100 条 |
| 传输缓存 | 单任务有界，初始目标不超过 4 MiB，另计计划元数据 |
| 无进度超时 | 60 秒，可由用户配置；整个大文件传输不设短时总时限 |

所有限制由 Rust 兜底，并在扫描和传输期间持续检查；文件增长不能绕过限额。前端百分比和字节数避免有符号 32 位转换。

目标可用空间能够查询时预检，不可查询时显示未知；写入遇到空间不足立即停止当前文件并清理临时项。临时替换需要额外空间，不能只计算最终文件大小。

## 7. 工作区、编辑器与运行产物

第一阶段：工作区右键仅带入传输选择，仍由同一队列执行。用户在另一侧浏览文件不切换当前工作区。

任务读取磁盘已保存内容。若源文件有未保存标签页，启动前提示先保存或传输磁盘版本；不能把编辑缓冲内容隐式混入普通复制。

写入当前打开的目标工作区时，刷新目录并通知相关编辑标签页外部变化。存在未保存改动的目标文件应阻止覆盖或要求用户先处理；远端与本机遵循一致规则。

第二阶段增加运行历史「浏览产物 / 下载产物」：

- 保存实际执行端点：设备 ID、传输类型、实际目录、是否原地执行。保留原始工作区来源，不通过可变的设备 `workspace_root` 猜测历史目录。
- SSH / WSL 使用实际运行目录进入文件浏览，再调用传输队列；先人工选择产物，不自动扫描整机。
- Local 原地运行提供打开本机目录；跨设备暂存到 Local 的运行需在临时目录清理前显式导出，不能在历史中提供已失效目录的下载入口。
- 目录被删、设备配置缺失或身份变化时显示不可用；串口暂不提供通用产物下载。
- 正在运行任务的文件可浏览，但变化检测不等于稳定快照；完成后的产物才适合作为默认下载入口。

## 8. 历史与恢复

建议独立 `transfers.json`，沿用现有应用数据目录和原子文件写入方式。

- 默认保留最近 100 个任务或 7 天，两者任一达到即淘汰已结束任务。
- 保存端点、名称、统计、结果、错误与临时文件清理记录；不保存文件内容、密码、私钥或完整凭据快照。
- 任务执行时的凭据仅驻留内存；重试从设备配置重新取得，并重新预检。
- 活动任务和未清理记录不能按普通历史直接淘汰。清理记录应有独立上限，超限提示人工处理。
- 重启恢复历史与中断状态，第一阶段不自动恢复字节偏移。

## 14. 同步启动传输导致主线程崩溃的修复（2026-10-13）

用户日志显示 `manager.rs` 在 `tokio::spawn` 处发生 `there is no reactor running`。`transfer_start` 是同步 Tauri IPC 命令，可在未进入 Tokio 运行时的 WebView 主线程执行；此前直接调用 `tokio::spawn` 依赖调用线程上的运行时。panic 随后越过不能展开的 Windows WebView 回调边界，触发进程终止；日志末尾的 `STATUS_STACK_BUFFER_OVERRUN` 是这次终止的退出状态，定位依据是前面的运行时 panic。

- `TransferManager::start` 改用 `tauri::async_runtime::spawn`，与现有运行和终端管理器一致，将后台传输提交到 Tauri 持有的运行时；无需改变同步命令接口。
- 新增回归测试：用本地 SSH / SFTP 仿真服务预检，在明确没有 Tokio 上下文的普通线程上调用 `start`，验证 100,000 字节二进制文件上传、下载完成且无残留。修复前该测试复现同一 panic，修复后通过。既有异步测试的运行时上下文曾掩盖这个问题。
- Rust 离线全目标测试通过：192 个库测试、6 个文件传输 SSH 集成测试、5 个 SSH 生命周期测试、3 个终端 SSH 测试；13 个需显式环境的库测试默认忽略。
- `Ubuntu-24.04` 的真实 WSL 文件传输测试通过，覆盖 65 MiB 文件往返、中文 / 隐藏文件 / 空目录、冲突策略及别名检查。前端 130 项测试、构建、Rust 格式及差异检查通过。外部 SSH 主机上的实际 UI 操作尚未复测。

此修改属于 Rust 后端，需重启开发应用载入。触发本次 panic 的任务尚未进入文件拷贝，已持久化的排队记录在重启后按既有规则恢复为中断状态。
